## 0. 목표

사람 움직임을 예측해 로봇이 **불필요 정지↓ + 부드러운 선제감속/회피**.
`CCTV → 검출(YOLO) → 추적(ByteTrack) → (x,z) 시계열 → 궤적예측(칼만/LSTM) → SSM`.
**시뮬이 시연 공간**(1차 목표는 시뮬 위 시연). 단, **실배포(실제 급식실)도 고려** = sim-to-real.

## 1. 🔴 지금 정해야 할 것 — front 뷰 vs top 뷰

이번 세션의 결론: **아직 미결정, 하지만 판단 근거는 다 모였다.** 결정을 가르는 축은 **(A) 시연 전용이냐 실배포까지냐** + **(B) top-down 검출이 파인튜닝으로 되느냐**.

| | **front (정면 오블리크 50°, 2.15m)** | **top (나디르, 직교/5m)** |
|---|---|---|
| 검출 (stock) | ✅ **0.8+ (학습 0으로 됨)** | ❌ 0 |
| 검출 (우리 overhead 모델) | — | ❌ **recall 0.17 / prec 0.30** (선반·설비 오탐) |
| 검출 (시뮬 파인튜닝) | 불필요할 수도 | ❓ **미검증 = make-or-break** |
| 먼 접근 커버 | ✅ 3.5m까지 | ✅ (직교면 전 동선) |
| (x,z) 좌표 | ⚠️ 오블리크 → 호모그래피 깊이 노이즈 | ✅ 최고(직교=순수 스케일) |
| **실배포(sim2real)** | ✅ **현실 높이·현실 카메라** | ❌ **직교=불가·5m=불가 (sim 전용)** |

**결정 규칙**:
- **실배포가 목표** → **front** (top은 직교/5m라 실제에 못 씀. 검출도 front만 실증됨).
- **순수 시연 + top-down 파인튜닝이 성공** → top (좌표 최고, 단 데모 한정).
- 미검증 지점 = **ds_top 파인튜닝이 top-down 검출을 살리는가**(특히 설비 오탐 억제). 이게 top의 유일한 생존 조건.

> 현재 무게추는 **front**로 기운다: 실배포 가능 + 검출 실증. top은 "시연 전용 + 파인튜닝 성공" 두 조건이 다 맞아야 산다.

## 3. 카메라 실측 (전부 GT 기준 = 사람이 "보이는" 크기, 모델 아님)

### 3-1. 카메라 각도 (dir 벡터)
- `top`(CAM4) = **수직 나디르 90°**, 5m, "설치 불가 가상 GT뷰"(코드 1765~).
- `overhead`(CAM1)=69° 경사(3.05m), `deg45`=45°, `corner`, `eye`, `front`=50°(2.15m, 통로감시).

### 3-2. 커버리지 — 거리별 person 검출(px, ✗=미검출)
| 로봇거리 | overhead69° | deg45 | corner | **front** | top나디르 |
|---|---|---|---|---|---|
| 3.5m | ✗ | ✗ | ✗ | **3347** | 2090 |
| 2.5m | ✗ | ✗ | ✗ | **3085** | 1910 |
| 2.0m | 724 | 671 | ✗ | 2964 | 2293 |
| 1.5m | 10122 | 5097 | 2082 | 1971 | 2788 |
| 1.0m | 12164 | 13747 | 23580 | 1607 | 2348 |

→ **먼 접근(2.5~3.5m)을 보는 실사 캠은 `front`뿐.** overhead/deg45/corner는 2m 안에서야 봄. top나디르는 보지만 설치 불가.

### 3-3. 직교(orthographic) top 실험 — 균일 검출 크기
- top을 **직교 카메라**로(런타임) → kettle·안전링이 **완벽한 원**(원근 0), 픽셀↔바닥 순수 스케일.
- **좁은 셀(6.6×4.95m, 145px/m)**: 작업영역 8곳 person **2800~3350px 균일**.
- **전 동선(8.5×6.4m, 113px/m, bbox x[-2.2,5.1] z[0,6.4])**: 8곳 person **1600~2000px, 박스~70×50 균일** → 구석까지 검출 가능 크기.
- **의의**: 원근과 달리 직교는 사람 크기가 프레임 전체에서 균일 → 미검출 사각 없음. 궤적이 안 잘림.
- **직교 top 설정(내일 생성용)**: center (1.45,3.21), 5m 나디르, span 8.5×6.4(4:3), ≈113px/m.

## 4. 🔴 검출 실측 (모델 실제 구동) — 이게 make-or-break

### 4-1. stock YOLOv8n (COCO, 미학습)
- **front**: 3.5m conf **0.82**, 전 구간 0.55~0.83 ✅ (정면 전신 = COCO가 아는 형태)
- **top/ortho**: **검출 0** (12프레임 전부, maxconf ≤0.18) ❌

### 4-2. overhead-person-yolo11 (`best.pt`, 우리 학습 모델·실사데이터) → 시뮬 나디르 top
GT IoU 매칭 정밀 평가 (ds_top 12프레임):

| | 값 |
|---|---|
| TP | 3 |
| FP | 7 (선반·설비 오탐) |
| FN | 15 |
| **recall** | **0.17** |
| **precision** | **0.30** |

- **결론: 안 됨.** 18명 중 3명만 맞힘, 검출 7건이 오탐(흰 선반/설비를 person으로). ortho_000 한 프레임만 제대로(2명).

- ⚠️ **정정 기록**: 세션 중 "top에서 잡힌다"고 성급히 판단했으나, GT 대조 결과 대부분 오탐/놓침이었음. confidence≠정답.

### 4-3. 종합
- **현재 어떤 모델도 시뮬 top-down person 검출 못 함** (stock 0, 우리모델 recall 0.17).
- **front만 실증됨** (stock 0.8+).
- top-down 생존 = **ds_top 멀티클래스 파인튜닝(kettle/equip/선반을 하드네거티브로)** 이 오탐을 잡고 recall을 올리느냐. **미검증 → 내일.**

## 5. sim-to-real 정리

**좌표로 넘어가면 대부분 도메인 불변** → 갭이 "검출기 픽셀" 한 곳에 몰림.

| 단계 | 갭 | 해소 |
|---|---|---|
| 검출 | **유일한 진짜 갭** | front이면 최소(정면은 stock이 실사도 됨). top-down이면 DR+실사혼합 필요 |
| 추적(ByteTrack) | 없음 | 박스 기하만 |
| 위치추정(호모그래피) | 갭 아님 | 실제 카메라 **현장 1회 캘리브** |
| 예측(칼만/LSTM) | 작음 | 좌표는 도메인불변. 칼만=0 |
| 안전(SSM) | 없음 | 수식 |

**핵심 제약**: 직교 카메라·5m 마운트는 **실제 불가**(실카메라는 원근, 천장 2.7~3.5m). → top(직교/5m)은 **시뮬 GT·데모 전용**, 실배포 검출기 타깃 못 됨. 실배포는 **현실 높이 원근 카메라** = front(2.15m 오블리크, 먼 접근 커버, 검출됨)이 답.

## 5b. 커버리지·가림·관측 — 예측 시스템의 근본 요구 (세션 후반 추가)

**핵심 원리: 예측은 관측이 있어야 성립.** `안 보임(FOV 밖 or 가림) → 트랙 없음 → (x,z) 없음 → 예측 불가.`

- **카메라 각도 ↔ 커버리지 관계**: **수직에 가까울수록(→나디르 90°) 더 많이 보고 가림이 적다.** 수평(0°, 눈높이)이 최악(모든 게 서로 가림, 좁은 띠만). 오블리크(front 50°)는 중간.
- **front(오블리크)의 한계 = 원뿔 시야 + 가림**: (1.5,-0.95)에서 향한 통로만 봄. FOV 밖·설비 뒤·원거리 사각은 안 보임 → **예측에 사각.**
- **top(나디르)**: 바닥 전체 + 위에서라 가림 거의 없음 → **어디서나 연속 관측** → 예측이 성립. ETH/UCY·ATC가 조감인 근본 이유.

**→ 예측 시스템 관점에선 근나디르 top-down이 근본적으로 맞다.** front은 검출은 되지만 "모든 곳을 못 봐서" 예측 사각이 생긴다.

**sim-to-real 화해안(현실적 정답)**: 순수 5m 나디르는 불가하지만, **실제 천장에 가능한 한 수직에 가까운 근나디르 카메라(~3m) + 광각/복수대로 커버·가림 보완 + top-down 검출기 파인튜닝.**

**front YOLO+ByteTrack 실측(접근로, 오프라인)**: 3.5m→1.5m 내내 검출 + **track id=1 안정 유지**(corner/eye의 ID 스위치와 대조). 1.0m서 conf 0.55로 미확정(-1). → **접근로(시야 트인 곳)에선 front 검출·추적 잘 됨.** 단 위 가림·커버 한계는 별개.

## 6. front으로 갈 때 (x,z) 얻는 법 — 호모그래피 발점 역투영

- **호모그래피 H**(3×3): 이미지 픽셀 ↔ 월드 바닥(x,z), 바닥평면에만 유효.
- **캘리브(고정캠당 1회)**: 바닥 아는 점 4개↑의 (x,z)↔(u,v)로 H. 시뮬은 카메라 파라미터로 직접 계산, 실제는 바닥 마커 측정.
- **런타임**: 검출 박스의 **발점(하단 중앙=바닥 접점)** → H → (x,z). (머리는 바닥 위라 틀림)
- **오블리크 한계**: 먼 거리 깊이축 노이즈 → 칼만 평활, 예측 σ 확대.
- **시뮬 검증 가능**: front 발점 역투영 (x,z) vs GT (x,z) 오차 실측 가능(front 확정 시 다음 측정).

## 7. 궤적 예측 (나중)

- 목표: Trajectron++식 조감 시각화(예측 경로 + σ 음영 + 로봇 반경). **칼만으로 지금 바로 가능**(학습 0). 시뮬에 `PRED.line`·`PRED.sigma`·`stopRing/slowRing` 이미 있음 → σ 음영+로봇 예측반경만 추가.
- 학습형(LSTM/Transformer/Diffusion/Trajectron++)은 `__customPredictor` 훅에 ONNX. 전부 **(x,z) 시계열 입력 = 카메라 무관**. ("NLP"는 궤적 방법 아님)
- **학습형용 시뮬 변경(나중)**: 현재 사람 이동 = 손 웨이포인트 직진(`SCN.approach/patrol`), `randomizeScene`은 위치·포즈만 랜덤 → 멀티모달 없음. **스테이션 목표그래프 + 랜덤 목표 샘플러** 필요(작은 패치). **지금 시뮬팀 요청 불필요** — 검출·칼만·ETH/UCY엔 안 씀.

## 8. 내일 체크리스트

1. **결정**: front vs top (§1 규칙). 실배포 고려하면 front 유력. top은 아래 실험이 성공해야 생존.
2. **top-down 파인튜닝 실험(make-or-break)**:
   - ds_top **재생성**(회사 PC, top 나디르 또는 직교, **멀티클래스**, 수백 장, kettle/equip/선반 하드네거티브).
   - ⚠️ **브라우저 탭 앞에 두기**(백그라운드면 렌더 정지 → groundTruth 멈춤). 이번 세션 최대 삽질.
   - ⚠️ 생성 카메라 = 직교 top(§3-3 설정) 또는 최소 나디르. 69° overhead 금지(먼 접근 미검출).
   - YOLO11 파인튜닝(RTX 5070) → **recall·precision, 특히 설비 오탐** 확인.
   - 되면 → top 직진(검출→ByteTrack→(x,z)→예측). 안 되면 → **front 확정**.
3. **front 확정 시**: front 호모그래피 (x,z) 오차 vs GT 측정(깊이 노이즈 정량).
4. **병행**: 칼만 기반 조감 예측 시각화(σ 음영+로봇 반경) — 학습 없이 데모.
5. 서버 의존성: `pip install fastapi uvicorn trackers supervision`.
6. 시뮬 실행: `python -m http.server 5173` → `http://localhost:5173/sim.html?person=1`.
