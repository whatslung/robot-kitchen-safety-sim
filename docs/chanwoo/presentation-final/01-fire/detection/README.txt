[12] 오려붙이기 - 파이프라인 시작
     파일: 12_composite_stirfry.png (볶음) · 12_composite_fryer.png (튀김)
---------------------------------------------------------------------
실제 급식실 배경에 NIST 조리유 화재 불꽃을 합성하고 검출 결과를 그린 것입니다.
왼쪽이 불 없는 원본(검출 0), 오른쪽이 합성 후입니다.
박스는 초록이 정답 위치, 빨강이 모델 검출입니다.

- 파인튜닝 없이도 기성 모델이 합성 조리유불을 인식합니다 (볶음 conf 0.85 · 튀김 0.81).
- ★ 같은 모델이고 바뀐 건 장면뿐입니다. 학습으로 성능이 올랐다는 뜻이 아닙니다.
- 불꽃은 실화재가 아니라 합성입니다.

[13] 부러지는 지점 - 크기
     파일: 13_scale_ladder.png
---------------------------------------------------------------------
같은 급식실 장면·같은 불꽃을 크기만 줄이며(0.40 -> 0.25 -> 0.11) 검출한 것입니다.
(위에서 아래로 축소, 크기가 유일하게 바뀐 변수)

- 크기 0.40·0.25: 5장 전부 검출
- 크기 0.11: 5장 중 3장만 검출 (2장 놓침, conf도 0.27까지 하락) = 여기서 무너지기 시작
- 초록=정답, 빨강=검출.
- 집계 recall은 크기 >= 0.25에서 0.994, 0.11에서 0.694입니다.
  (이 그림은 경향의 "예시"입니다 - 3/5는 5장 샘플이라 이 비율 자체를 결론으로 쓰지 마세요.)
- 결론: 크기가 가장 큰 한계이고, 조기(작은) 불 검출이 진짜 과제입니다.
  (화질·조명도 한계이나 크기가 지배적입니다.)

[14] ablation - 이미지 2종, 서로 다른 이야기
     파일: (1) 14_lever_table.png + 14_over_vs_screen.png   [방법 레버 · 2장]
           (2) 14_diagnosis.png                             [두 병목 진단 · 1장]
---------------------------------------------------------------------
(1) 방법 레버
어떤 합성법이 효과 있는지 비교한 것입니다.
(VFX 26장면 x 배경 18 x 크기 3, 5조건, rec@IoU0.5)

- over가 screen보다 1.55~2.20배 높음 (밝은 조리면에서 screen은 불꽃을 흰색으로 지움)
- 배치(랜덤 vs 조리면)는 차이 없음, 반사광은 작은 불에서만 도움, 크기가 가장 큰 요인
- ★ 여기 숫자(0.16~0.50)는 rec@IoU0.5 (박스가 위치까지 정확한가) 입니다.
  13번의 0.994 (불꽃이 검출되나) 와는 다른, 더 엄격한 지표라 낮게 나오는 것이고,
  그 격차가 바로 (2)의 위치 병목입니다.
  (1)은 방법 비교용이지 절대 성능이 아닙니다.

(2) 진단
낮은 recall이 사실 서로 다른 두 병목이라는 진단입니다.

- 왼쪽: 작은 불은 아예 못 잡음 (실효 21px) = 검출 병목
- 오른쪽: 큰 불은 검출은 하는데 박스가 밝은 코어만 = 위치 병목
- ★ 오른쪽에서 빨강이 초록보다 작다고 "모델이 박스를 못 그린다"로 읽으면 안 됩니다.
  base는 원본 D-Fire 관행대로 밝은 코어를 tight하게 박싱하는 게 정상이고,
  우리 정답 박스가 헐거운 것입니다.
  base 정상, 우리 측정 설정 문제이고 둘 다 고칠 수 있습니다.
- (2)는 "검출 성공"이 아니라 "왜 recall이 낮은지 진단"하는 이미지입니다.

발표팁: (2) 왼쪽 불꽃이 매우 작으니(실효 21px, 화면에서 잘 안 보임),
        초록 박스를 가리키며 "이만큼 작으면 모델도 못 봅니다"로 설명하면 좋습니다.
