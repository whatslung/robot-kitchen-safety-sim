## 1. 조리로봇 안전 AI
**상태**: 🟡 수정 (원본 p1) — 히어로 이미지 신규(회피+화재감지) · 지표 3축 도메인(0.81/0.98/0.93)으로 교체.
**배치**: 중앙에 대형 히어로 이미지 · 상단에 제목+헤드라인 · 하단에 지표 3분할 띠 · 최하단에 팀.
**그래프·에셋**: 🖼 히어로 이미지 1장(필수). 지표는 텍스트(이미지에 새기지 말 것).

- 제목: 조리로봇 안전 AI
- 헤드라인: 불은 번지기 전에, 사람은 부딪히기 전에 — 예측해서 먼저 대응합니다
- 태그라인: 합성으로 위험을 배우고, 사람의 다음 1.6초를 예측해 화재·충돌에 선제 대응하는 피지컬 AI 안전 시스템
- 하단 지표 3분할: 화재 합성 검증 recall **0.81** (base가 합성 불꽃 인식·게이트 통과) · 천장 사람 검출 recall **0.98** (실사 학습·REAL) · 위험 진입 예측 recall **0.93** (통제 시뮬·SIM)
- 팀: 문경호 · 배찬우 · 위성배 · 안재휘 | 멘토 이예찬

`에셋: 히어로 = 표지 전용 **깔끔한** 이미지(Figure Lab 신규 권장). 상세 시스템 일러스트(장비 많고 라벨 많은 그 그림)는 S4로 옮김 — 표지엔 더 아이코닉하게(로봇 팔 후퇴+작업자+화재 박스 정도로 크롭/단순화, 헤드라인 공간 확보). 시각 요소만: 후퇴 화살표·예측 경로 점선·화재 감지 박스·안전링. 영어 라벨 제거(필요시 젠스파크 한글). ⚠️ 화재 숫자: "0.81(합성 검증)" 사용, "0.90(실사 학습)"은 미증명이라 폐기. 사람 0.98은 상한값(S11서 0.84 해소).`

## 2. 위험한 순간은, 찍을 수 없습니다
**상태**: 🟡 수정 (원본 p2) — 3카드 구조·텍스트 **유지**, 사진 1장만 교체(교통사고 → 로봇 끼임), 화재는 주방화재 권장.
**배치**: 상단에 3카드 가로 분할(각 카드 = 이미지 + 캡션) · 하단에 2박스 대비(반응형 ↔ 선제형).
**그래프·에셋**: 🖼 실사 뉴스 사진 3장. 그래프 없음.

- 부제: 안전을 가르치려면 위험을 보여줘야 하는데 — 그 위험을 만들 수가 없습니다
- 카드 1 · 화재 (촬영 불가): 급식실에 불을 낼 수 없다. 발화 장면을 학습용으로 찍을 방법이 없다
- 카드 2 · 사고 (재현 불가): 사고는 한 번 난 뒤에야 기록되고, 다시 만들 수 없다
- 카드 3 · 충돌 (사용 불가): 사람이 다친 실제 영상을 학습에 쓰는 것은 윤리 문제다
- 결론 한 줄: 세 경우 모두 → 학습 데이터가 없다
- 하단 대비: [지금·반응형] 센서가 접촉을 감지한 뒤 멈춤 = 이미 늦음  ↔  [우리·선제형] 다음 경로를 예측해 미리 물러섬

`에셋: 뉴스 3컷 전부 외부 직접 소싱(출처 표기). 화재=실사 주방 화재 · 사고=로봇 끼임/협착 · 충돌="사람을 상자로 오인, 로봇에 눌려 사망". ⚠️ 우리 합성 불꽃 쓰지 말 것(못 찍는다와 모순).`

## 3. 기성 기술은, 두 곳에서 막힙니다
**상태**: 🟢 유지 (원본 p3) — 레이아웃·수치(3.2초·0.175) 그대로. 유일 변경 = 하단 "세 가지 답"의 슬라이드 번호 참조 갱신.
**배치**: 2분할 — 좌(장벽1·속도)=가로 막대 그래프, 우(장벽2·인식)=천장 탑뷰 사진 + 큰 빨강 숫자 · 하단에 "세 가지 답" 3-아이템 스트립.
**그래프·에셋**: 📊 막대 그래프 1(속도) + 🖼 탑뷰 사진 1(인식).

- 부제: 데이터를 구해도 — 현장에 넣으면 두 번 무너집니다
- 장벽 1 · 속도: 원격 대형 모델은 호출에 3.2초. 사람은 1초에 1.6m라 판단이 도착하면 이미 5.1m 전 장면. 우리는 온디바이스 0.1초
- 장벽 2 · 인식: 5m 천장에서 본 사람은 기성 검출기가 못 찾는다. recall 0.175 = 10명 중 8명을 놓침. 공개 데이터는 눈높이 시점이라 위에선 머리·어깨만 남음
- 하단 브리지 — 이 발표의 세 가지 답: ① 온디바이스 0.1초 판단  ② 나디르 재학습 + 4분할  ③ 없는 데이터는 합성

`에셋: 좌 막대 = 3.2초(대형 VLM) vs 0.1초(온디바이스), 젠스파크 생성 가능. 우 사진 = 천장 탑뷰 군중 실사(기존 p3 것 재사용 또는 소싱) + 빨강 0.175 오버레이. 이 슬라이드는 원본 p3와 거의 동일 — 하단 답의 슬라이드 번호만 새로.`

## 4. 그래서, 세 가지를 직접 만들었습니다
**상태**: 🟡 수정 (원본 p4) — **번호 콜아웃 = 목차** 방식. 베이스는 **실제 sim 아이소메트릭 뷰**(라인아트 아님 — 진짜 시뮬이라 신뢰도↑·전체 조망). 그 위에 ①②③ 리더선 콜아웃.
**배치**: 실제 sim 아이소메트릭 스크린샷(주방 전체 조망) 위에 번호 콜아웃 3개 + 리더선 라벨. 여백에 라벨.
**그래프·에셋**: 🖼 sim 아이소메트릭 뷰 1 + ①②③ 콜아웃 오버레이. 그래프 없음.

- 콜아웃 3개 = 발표 순서: ① 화재 감지(→S5~S8) · ② 이동 예측(사람 검출+경로, →S9~) · ③ 회피(→라이브 시연)
- 발표 오프닝: "오늘 이 세 가지를 보여드립니다" 하고 번호를 짚으며 전체 지도 제시

- 부제: 세 장벽에 세 해법을 1:1로 — 이 장이 발표의 목차입니다
- 화재 (촬영 불가) → 합성 데이터로 학습 + 노이즈 9종 증강
- 사람 (검출 0.175) → 나디르 재학습 + 공간 4분할·월드 융합
- 속도 (3.2초) → 온디바이스 0.1초 + 다음 1.6초 예측 (ISO/TS 15066)
- 핵심 한 줄: 없는 데이터는 만들고, 안 보이는 시점은 다시 배우고, 느린 판단은 현장 장비로 앞당겼다

`에셋: 베이스 = 실제 sim 아이소메트릭 스크린샷(사용자 캡처). 그 위에 콜아웃 ①화재감지 ②이동예측 ③회피 (리더선+한글 라벨) 오버레이 — 젠스파크에서 얹거나, 스크린샷 파일 주면 내가 Python으로 오버레이(한글폰트 malgun). 이상적으론 불+예측경로 켠 프레임으로 캡처(①②가 진짜 이벤트 가리킴). 없으면 위치 콜아웃으로 충분. p4 장벽→해법 논리는 S3 하단 "세 가지 답"이 담당하므로 S4는 목차 뷰로 단순화.`

## 5. 불을 못 내니 합성으로 만들고, 증강으로 어떤 화면에서도 잡습니다
**상태**: 🟡 수정 (원본 p5) — **파이프라인 과정만** 남김. ⚠️ 옛 결과 숫자(ablation 0.81→0.005 · 실사 전이 0.31) **제거** — journey md와 방향 충돌(그건 train-on-synthetic 옛 방식). 결과 숫자는 전부 S8로. 우측 "도식 읽는 순서" 컬럼·하단 번호 네비도 제거.
**배치**: 중앙 대형 워크플로우 도식(figure) 1개. **결과 숫자 콜아웃 없음** — 과정만.
**그래프·에셋**: 🖼 워크플로우 도식 1 (기존 p5, 작은 schematic 썸네일 포함). 큰 이미지는 S6·S7 담당.

- 부제: 화재 축 전체 흐름 — 데이터를 만들고(합성), 어떤 화면에서도 잡게 하고(증강), 학습·판정
- 흐름: 실사 주방 배경 → 진짜 불꽃 오려 합성 → 자동 박스(GT) → 노이즈 9종 증강 → YOLO11s 학습 → 화재 감지 평가

- 예고: 다음 두 장 = S6 합성(어떻게 만드나) · S7 증강(어떻게 강건하게)

`에셋: 도식 = 기존 p5 figure 재사용, 단 편집 필요 — 도식에서 "Ablation 0.81→0.005" / "실사 전이 test 0.31" 두 숫자 콜아웃 **삭제**(흐름 박스·화살표는 유지). ✅ "합성 화재 + 자동 박스(auto bbox)" 그대로 OK — 오려붙이기라 위치를 아니까 박스 자동. p5 figure를 Figure Lab에서 다듬어 재생성 권장(숫자 제거 + 깔끔).`

## 6. 급식실 불을, 두 방식으로 합성합니다
**상태**: 🟡 수정 (원본 p6 재구성) — 합성 방법 2가지(오려붙이기 + 생성형)를 나란히. 오려붙이기가 S8 결과와 방법 일치.
**배치**: 2분할 — 좌 = 오려붙이기(불꽃 뱅크 26장 → 급식실 합성, 박스 자동) · 우 = 생성형(GPT·Nano Banana 생성, 박스 수동).
```
┌───────────────────────────────┬──────────────────────────┐
│ ① 오려붙이기 (진짜 불꽃)         │ ② 생성형 (AI)             │
│ ───────────────────────────── │ ──────────────────────── │
│ 불꽃 뱅크 (VFX 26장 · CC0)      │ GPT · Nano Banana 생성    │
│  [flame_bank_grid]            │  [생성 급식실 불 3~4장]    │
│    ↓ 급식실 배경에 합성          │                          │
│  [합성 예시 1컷]                │                          │
│  → 박스 자동 (붙인 위치 앎)      │  → 박스 수동 (위치 모름)   │
└───────────────────────────────┴──────────────────────────┘
   진짜 불꽃을 잘라 붙임              AI가 장면을 통째로 생성
```
**그래프·에셋**: 🖼 불꽃 뱅크 그리드 1 + 합성 예시 1(좌) · 🖼 생성형 예시 3~4(우). 그래프 없음.

- 부제: 진짜 불꽃을 오려 붙이거나(compositing), AI로 생성해(generative) 학습 데이터를 만듭니다
- ① 오려붙이기: 검은 배경 불꽃(VFX 26장·CC0 + NIST 조리유) 알파 추출 → 급식실 배경에 크기·위치 랜덤 합성. **붙인 위치를 아니까 박스 자동**(라벨 공짜)
- ② 생성형: GPT·Nano Banana가 급식실 불 장면을 통째로 생성 → 위치를 모르니 **박스 수동**(Roboflow)

## 7. 현장 CCTV는 깨끗하지 않습니다 — 9종 노이즈로 미리 겪게
**상태**: 🟡 수정 (원본 p7) — ⚠️ **모순 수정**: 원본 그리드 헤더가 "학습 시 적용하는 **9종**"인데 3종은 [held-out](학습 안 함) → "수증기 학습했냐"로 걸림. **6종(학습)과 3종(시험용)을 시각적으로 확실히 분리.** + 상세 severity 차트(fp_rate/flame_rate)는 **부록**으로.
**배치**: 상단 = **학습 6종 그리드**(gaussian~contrast) · 그 아래(또는 옆) **따로 떼서 "시험용·학습 안 함 3종"**(steam·grayscale·erasing) 작게 + 큰 라벨. 하단 = 센서 열화 4컷(선택).
**그래프·에셋**: 🖼 학습 6종 그리드 + 🖼 시험용 3종(분리). 그래프 없음(상세 severity 차트는 부록).

- 부제: 저해상·압축·수증기로 덮인 현장. 깨끗한 영상만 학습하면 무너집니다
- 왜: 급식실 CCTV는 저해상·압축·수증기 → 깨끗한 데이터로만 학습하면 현장서 실패 → 학습 때 노이즈를 미리 겪게 함
- **학습에 쓴 6종**: gaussian·jpeg·motion_blur·defocus·low_light·contrast
- **시험용·안 가르친 3종 (학습 X)**: steam(수증기)·grayscale(흑백)·random_erasing(가림) — "학습에서 본 적 없는 것에도 버티나" 시험지
- ⚠️ 헤더에서 "학습 시 적용 9종" 문구 금지 — "노이즈 9종 = 학습 6 + 시험 3"으로. steam은 **학습 안 함**을 명확히.
- 성과 한 줄(S7에 유지): 안 가르친 steam(수증기)에도 헛경보 낮음 = **"김을 불로 착각 안 함"** (상세 차트는 부록)

## 8. 불 나면 잡고, 안 나면 안 울립니다
**상태**: 🔵 추가 (원본 p8 표 → 결과 이미지+그래프로 전면 재작성) — "결과(전)" 구간 시작.
**배치**: 좌 = before/after 검출 이미지 2쌍(볶음·튀김) · 우 = 큰 숫자 타일 2(실화재 recall 0.93 · 헛경보 0.7%). **그래프 없음**(화재는 지표가 종류·방향이 달라 그래프가 오히려 헷갈림 → 숫자 타일).
```
┌────────────────────────────┬───────────────┐
│ before/after ① 볶음          │  실화재 recall │
│  불 없음(검출 0) → 검출됨 0.85 │     93%       │  ← 숫자 타일(그래프 아님)
│ ─────────────────────────── ├───────────────┤
│ before/after ② 튀김          │   헛경보       │
│  불 없음(검출 0) → 검출됨 0.81 │     0.7%      │  ← 숫자 타일
└────────────────────────────┴───────────────┘
   좌: object detection 이미지 2쌍        우: 큰 숫자 2개
```
**그래프·에셋**: 🖼 before/after 검출쌍 2 + 숫자 타일 2. (크기 사다리는 **부록으로 이동** — 결과는 긍정 톤 유지)

- 부제: 실제 화재는 93% 잡고, 불이 없으면 거의 안 울립니다 — 합성 급식실 불꽃도 검출
- **실제 화재 검출**: 공개 실화재 이미지에서 recall **0.93** (운영점 conf 0.25)
- **헛경보 거의 없음**: 실제 급식실 무화재 영상 684장에서 오경보 **0.7%** (같은 운영점) → "불 나면 93% 잡고, 안 나면 0.7%만 헛울림"
- **합성 급식실 불꽃도 검출**: 불이 없으면 검출 0 → 합성 불꽃을 넣으면 검출됨 (예시 conf 0.85·0.81) (before/after)

`발표자 노트: ① 실화재 recall 0.93 = 공개 D-Fire 이미지에서 불을 잡은 "비율"(rate). ② 이미지의 0.85·0.81은 그 한 장의 "검출 신뢰도(conf)"지 recall 아님 — 두 숫자는 종류가 다르니 비교하지 말 것. ③ precision 대신 헛경보율 쓰는 이유 = 화재는 안 난 때가 대부분이라 precision이 크게 흔들림 → "안 났을 때 몇 % 헛울리나(0.7%)"가 더 안정·의미. ④ base mAP50 0.660. 크기 사다리(0.99→0.69)는 부록. "실사 학습 실전 개선"은 진짜 급식실 불 데이터가 다음 관문.`

`발표자 노트(슬라이드엔 X): base=공개 D-Fire mAP50 0.660 · 합성 검증 recall 0.81(게이트 통과). "실사 학습으로 실전이 좋아지나"는 진짜 급식실 불 데이터 확보가 다음 관문. 질문 오면 이렇게 답.`
