# 궤적 데이터 수집 — 설계 (확정)

> 2026-08-19 브레인스토밍에서 확정. 이슈 #2의 **2단계**. 1단계(스테이션 전이 모델,
> `2026-08-20-station-transition-design.md`)가 만든 WORKFLOW 동선을 켜고 돌려
> 사람 궤적을 뽑아 저장한다. 3단계(베이스라인 ADE/FDE)·4단계(학습형 예측기)의 입력이 된다.

## 문제

1단계로 사람 동선에 학습 가능한 구조(직무 사이클 기반 불균등·문맥의존 전이)가 생겼다.
이제 그 동선을 **좌표 시퀀스로 기록**해 예측기 학습 데이터를 만들어야 한다. 시뮬엔
사람 위치가 매 프레임 있지만, (a) 저장 스키마, (b) 에피소드 경계, (c) 2.5Hz 리샘플링,
(d) 다인원 동시 기록 — 새 설계 결정이 필요하다.

## 결정 요약 (브레인스토밍)

| 결정 | 값 | 근거 |
|---|---|---|
| 위험 라벨(far/caution/danger) | **학습 입력에서 제외**, scene 메타로만 보존 | 학습형은 동선·목표를 배우지 위험등급을 배우지 않는다. 위험판정은 하류 SSM 몫. blocker(5직무 전부 danger)를 2단계에서 안 건드림 |
| 저장 단위 | **scene(장면) 연속 기록** — 한 실행에 여러 사람 공유 타임라인 | Trajectron++ 표준. 윈도우 자르기는 학습 준비 단계로 미룸. 이웃 상호작용을 나중에 옵션으로 살릴 수 있음 |
| 좌표 | 월드 바닥 **(x, z) 미터** 직접 | 실측 위치를 알고 있으므로 카메라 역투영 불필요 |
| Hz | **2.5Hz (dt=0.4s)** | Trajectron++ 관례(관측 8스텝=3.2s / 예측 12스텝=4.8s) |
| 저장 경로 | `dataset/trajectories/<scene_id>.json` | `dataset/`가 이미 gitignore(규약 준수) |
| 규모(기본) | **40 scene × 2~3명 × 60초** ≈ 15,000 사람-스텝 | 다양성·양 균형. scene 수는 파라미터 |

## 데이터 모델

scene 하나 = JSON 파일 하나. 파일 안에 여러 노드(사람)가 **같은 프레임 인덱스**를 공유한다.

```jsonc
{
  "scene_id": "island_seed7_0000",  // 레이아웃_시드_연번
  "schema": 1,                       // 스키마 버전
  "seed": 7,                         // 이 scene의 난수 시드 (재현 키)
  "layout": "island",                // 배치
  "wf": true,                        // WORKFLOW(직무 전이) 모드로 생성됐는가 (반드시 true)
  "hz": 2.5,
  "dt": 0.4,                         // 스텝 간격(초)
  "steps": 150,                      // 이 scene의 총 스텝 수
  "discarded": false,                // 노드 하나라도 순간이동으로 폐기표시되면 true (빠른 필터용)
  "nodes": [
    {
      "id": "extra_0",               // 추가 인원 (주인공은 기록 안 함)
      "job": "prep",                 // 직무 (scene 내 고정, 노드 속성)
      "role": "caution",             // jobRole() 값 — 메타(참고)로만, 학습 입력 아님
      "discarded": false,            // 이 노드에 순간이동(코드 산물)이 있었나 — 노드별 정밀 필터
      "frames": [
        // t=시작 기준 상대초. x,z=사람 바닥 위치. goal=지금 향하는 목표 스테이션 키,
        // gx/gz=그 좌표. moving=이동 중 여부.
        {"t": 0.0, "x": 1.23, "z": -2.10, "goal": "wrack", "gx": -2.95, "gz": 0.40, "moving": true},
        {"t": 0.4, "x": 1.10, "z": -1.98, "goal": "wrack", "gx": -2.95, "gz": 0.40, "moving": true}
        // …
      ]
    }
    // extra_0, extra_1 …
  ]
}
```

설계 판단:
- **`goal`을 매 스텝 기록.** goal-conditioned 예측을 열어두고, 목표 도달 순간이 데이터에
  드러나 세그먼트를 나중에 잘라낼 수 있다.
- **`role`은 scene/노드 메타에만.** 프레임 배열에는 위치·목표만 — 학습 입력에 위험 라벨이
  새지 않는다. blocker를 고친 뒤 재분석할 때 참고로 남긴다.
- **모든 사람 같은 프레임 인덱스(공유 타임라인).** 이웃 상호작용을 나중에 옵션으로 살릴 수 있다.

## 구동 — 고정 dt 동기 스테핑 (구현 중 결정, 2026-08-19)

당초 스펙은 실시간 렌더 루프(가변 dt)를 상정했으나, 구현 착수 시 실제 코드와 어긋남을
발견해 **고정 dt 동기 구동**으로 바꿨다. 근거:

- 실시간 렌더 루프는 `dt = now - last`로 매 프레임 dt가 달라 **같은 시드라도 좌표가
  미세하게 달라진다** → §5.1의 "글자 단위 동일"이 실시간에선 불가능.
- 궤적은 사람의 **월드 좌표를 직접 읽으므로 GPU 렌더가 불필요**하다(데이터셋 이미지 캡처와
  다른 점). 따라서 `scene.render()` 없이 `extrasUpdate`를 고정 dt로 직접 호출하면 된다.
- 고정 dt면 (a) 좌표가 결정적이고, (b) 백그라운드 탭에서도 돈다(함정 #1 해소 — rAF에
  의존하지 않는 동기 루프), (c) 실시간보다 빠르다(40 scene을 몇 분에). `__sim`이 이미 쓰는
  "렌더 루프와 무관하게 고정 dt로 궤적을 잰다"는 패턴과 같다.
- **sim-to-real 관점에서도 유리**: 실제 궤적 데이터셋(ETH/UCY 등)이 2.5Hz 균일 간격이라,
  고정 dt 균일 샘플링이 실제 도메인과 더 잘 맞는다. 모션 사실성은 적분식이 같아 불변이다.

구동 방식:
- **작은 서브스텝 dt(기본 40ms)로 잘게 밟고**, 위치는 **400ms마다(=서브스텝 10회) 스냅**한다.
  한 번에 400ms를 통째로 적분하면 목표를 지나치거나 충돌·길찾기를 건너뛴다 → 순간이동·끼임.
- 구동 대상은 모션에 필요한 최소 집합: `extrasUpdate(dt)` + `resolvePeopleSeparation()`.
  로봇·조리·안전 판정은 궤적과 무관하고, 빼면 전역 RNG 소비가 사람 모션에만 국한돼 결정성이 는다.
- **기록 대상은 추가 인원(extras)만.** 주인공(`person`)은 WASD·카메라 종속이라 결정성 부담이
  크고, 핸드오프도 "궤적 양은 추가 인원에서 나온다"고 했다.
- **순간이동 방지 ≠ 급정지/급가속 제거**(중요): 급가속·급정지·장애물 반응은 **버릴 노이즈가
  아니라 배워야 할 신호**다(예측기가 잡아내야 할 의도 변화·다봉성). 실시간과 같은 충돌·정체·
  감속 코드(`extrasUpdate`)를 작은 dt로 밟으므로 이 행동은 데이터에 그대로 남는다 — 급정지는
  `moving:false`로, 감속은 스텝 간 이동량 감소로. 폐기 대상은 **물리적으로 불가능한 좌표 점프**
  (재스폰·`setPathTo` 경로 재설정·콜라이더 튕김 같은 **코드 산물**)뿐이다. 이게 남으면 3단계
  칼만이 거대 속도를 추정해 오염된다(함정 #3).
- **임계값 원리**: 정상 최대 이동 = 최대속도(~0.9 m/s)×0.4s ≈ 0.36m. 우회·밀림 여유를 더해
  임계를 **0.8m**로 잡으면 정상 감속·가속·장애물 반응은 걸리지 않고 수 m 점프만 잡힌다. scene
  시작 후 안정화 서브스텝(기본 1초) 뒤 첫 스냅. 임계 초과 시 그 scene을 `discarded=true`로
  표시(저장은 하되 학습에서 거른다). 임계값은 **스텝별 이동량 히스토그램으로 실측 검증**해
  "정상 모션(≤~0.4m)"과 "순간이동(수 m)" 사이 빈 구간에 앉는지 확인하고 필요시 재조정한다.
- **화면 상태와 독립**(함정 #2): 사람의 월드 좌표를 직접 읽는다 — 예측 띠·화살표 등
  시각화 메시에 오염되지 않는다. `/traj` 저장은 카메라/뷰 상태와 무관.

## 저장 — `/traj` 엔드포인트

`backend/detect_server.py`에 `/dataset`·`/shot`과 같은 패턴으로 추가:

- scene 완결 시 시뮬이 **scene JSON 전체를 한 번 POST** → 서버가
  `dataset/trajectories/<scene_id>.json`으로 기록. 폴더 선택창 없음, 클릭 0회.
- 응답 `{ok, count, dir}` — 누적 scene 수로 진행률 확인.
- scene당 60초·3명·2.5Hz면 JSON 수십 KB라 통째 전송에 부담 없음.

## 자동 구동 하네스

버튼 하나(또는 `__sim.trajRun(...)`)로 시드를 순환하며 scene을 고정 dt로 자동 생성한다.

```
for 각 scene k in [0 .. N):
  sceneSeed = 기준시드 + k
  1. 재시드: RNG.reseed(sceneSeed) · TRAJ.seedBase=sceneSeed · EXTRA_GEN=0 · WF.on=true
  2. 시나리오로 extras 스폰 (scene마다 순환 → 직무 조합 다양성)
  3. 안정화 서브스텝(기본 1초) — 스폰 직후 좌표 점프가 데이터에 안 들어가게
  4. 고정 dt 루프: 40ms 서브스텝, 400ms마다 스냅 → 60초(150스텝) 기록
  5. scene JSON을 /traj로 POST
정지: 목표 scene 수(기본 40) 도달
```

- **재시드로 in-page 반복**(리로드 불필요). `RNG`에 `reseed(seed)` 추가, `extraSeed`가
  하네스 활성 시 `TRAJ.seedBase`를 쓰게 함 → scene마다 사람 시드가 `sceneSeed+7919·(i+1)`로 결정적.
- 시드 = scene 다양성. 시나리오도 scene마다 순환(cook+carry / cook+lead / prep+wash / 3인 등)해
  직무 조합을 다양화한다.
- **고정 dt라 실시간보다 빠르다** — 소요는 프레임 처리 속도에 좌우(수 분 규모), 벽시계 60초에 안 묶인다.
- **stride(윈도우 간격)는 학습 준비(3~4단계) 파이썬에서 정한다.** 2단계는 raw를 넉넉히 남긴다.
- 진입점: 데이터 탭 버튼 + `__sim.trajRun({scenes, seed, seconds, jobs})` 형태로 노출(파라미터화).

## 규모 견적

학습 샘플은 저장된 연속 궤적을 나중에 윈도우(관측8+예측12=20스텝)로 잘라 만든다.

고정 dt 구동이라 벽시계 시간에 묶이지 않는다(수 분 규모, 프레임 처리 속도에 좌우).

| 규모 | scene | 인원(extras) | scene 길이 | 총 사람-스텝 | 학습샘플(윈도우) |
|---|---|---|---|---|---|
| 작게 | 20 | 1~2 | 60초(150스텝) | ~4,500 | stride4 ~1,100 |
| **표준(기본)** | **40** | **1~2** | **60초(150스텝)** | **~9,000** | stride4 ~2,300 / stride1 ~9,000 |
| 넉넉 | 60 | 1~2 | 60초 | ~13,500 | stride1 ~13,000 |

> extras 수는 시나리오당 1~2명(주인공 제외). 사람-스텝이 부족하면 scene 길이·수를 늘리거나
> 3인 시나리오(`jobs` 인자)를 섞는다. stride 선택으로 학습 샘플 수를 조절한다.

## 재현성 & 검증 (성공 기준)

"된다"고 말하기 전에 실측을 붙인다(핸드오프 권고, 1단계 결함이 다 이걸로 잡혔다).

1. **재현성** — 같은 기준시드로 두 번 생성 → scene JSON의 좌표가 **글자 단위 동일**
   (고정 dt + 재시드라 이제 연속 좌표까지 결정적. 실시간에선 불가능했던 것).
2. **Hz 실측** — 기록된 스텝 간격이 정확히 0.4초, scene당 스텝 수가 목표대로.
3. **순간이동 0** — 스텝별 이동량 히스토그램에 수 m 점프 없음(폐기 scene 0에 근접). 급정지/
   급가속은 정상 신호로 유지됨을 함께 확인(이동량이 0~0.4m에 분포, 급정지 구간은 0 근처).
4. **WF 구조 유지** — 방문 분포가 불균등(1단계 실측처럼) — 균등 랜덤이 아님을 확인.
5. **학습 필드에 role 없음** — 프레임 배열에는 위치·목표만, `role`은 메타 위치에만.
