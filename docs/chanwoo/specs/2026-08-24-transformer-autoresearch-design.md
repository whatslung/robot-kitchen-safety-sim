# Transformer 자동 실험과 궤적 데이터 v2 — 설계

> 작성 2026-08-24 · 담당 chanwoo · 상태: **설계 — 승인 대기**
> 기준 브랜치: `chanwoo/traj-cvae-2026-08-24` · 기준 커밋: `6e16b9c`
> 실험 브랜치: `chanwoo/autoresearch-transformer-2026-08-24`

## 0. 결론

이번 실험은 **Transformer를 우선 개선하고 LSTM은 비교 기준으로 유지**한다. Karpathy의
`autoresearch` 코드를 궤적 모델에 그대로 붙이지 않는다. 대신 다음 운영 원칙만 가져온다.

- 데이터와 평가 방법을 먼저 잠근다.
- 모델 후보 파일 하나만 반복해서 바꾼다.
- 모든 시도와 실패를 순서대로 기록한다.
- 같은 시간 안에서 비교하고, 좋아진 시도만 남긴다.
- 최종 test는 승자를 고정한 뒤 한 번만 실행한다.

현재 120개 scene 데이터는 학습과 빠른 회귀 확인에는 쓸 수 있지만, 이번 실험의 **새 최종 test로는
쓰지 않는다**. 해당 test 수치가 이미 PR 본문과 검토 과정에 공개되어 모델 선택에 간접 사용됐기
때문이다. 같은 생성기로 150개 scene을 다시 만들고, 이전에 보지 않은 seed 41~50을 잠근 test로 쓴다.

## 1. 목표와 성공 기준

### 1-1. 목표

8개 관측점(3.2초)으로 12개 미래점(4.8초), 3개 경로 후보를 내는 현재 계약은 유지한다. 모델의
목적은 단순 위치 오차 최소가 아니라 **1.6초 안에 정지반경으로 들어오는 사람을 놓치지 않으면서
헛정지를 줄이는 것**이다.

### 1-2. 1차 지표

validation의 safety F2를 1차 지표로 쓴다. F2는 recall(실제 위험을 잡은 비율)에 precision(경보가
맞은 비율)보다 네 배 큰 가중치를 주는 균형 점수다.

`F2 = 5 × precision × recall / (4 × precision + recall)`

같은 경보 방식, 정지반경, 1.6초 지평선을 모든 후보에 적용한다. 후보가 다음 보호 조건을 모두
통과해야 비교 대상이 된다.

1차 F2는 배포 경로와 같은 `trajectory.risk.track_risk`로 계산한다. 고정값은 현재 시뮬레이터의
`stopR=3.10`, `horizon=1.6s`, `safeKsig=1.0`, `safeTau=0.1`이다. 즉 정지반경에 들어오는 모드의
확률 합이 0.1 이상이면 경보로 본다. 현재 이미 반경 안인 창은 선제 예측 대상에서 제외한다. FDE는
가중치가 가장 높은 한 경로의 네 번째 예측점으로 잰다. 이 값과 판정법은 탐색 중 바꾸지 않는다.

| 보호 조건 | 기준 |
|---|---|
| safety recall | 새 v2 Transformer 기준 모델보다 1%p 넘게 하락하지 않음 |
| 1.6초 FDE | 기준 모델의 1.02배 이하 |
| CPU p95 지연 | 기준 모델의 1.20배 이하 |
| 학습 가능 파라미터 수 | 기준 모델의 1.20배 이하 |

CPU p95는 같은 컴퓨터와 프로세스 설정에서 단일 궤적 `predict_batch`를 100회 준비 실행한 뒤
1,000회 재서 95번째 백분위로 계산한다. 파라미터 수는 `requires_grad=True`인 텐서의 원소 합이다.
실험 중 하드웨어나 PyTorch 버전이 달라지면 결과를 같은 순위표에 섞지 않는다.

### 1-3. 완료 기준

- 최소 성공: 보호 조건을 모두 지키면서 validation F2가 새 기준보다 **0.01 이상** 상승한다.
- 도전 목표: 같은 v2 데이터로 다시 잰 CVAE의 validation F2도 넘는다.
- 상위 후보 3개를 각각 모델 초기화 seed 3개로 재학습하고 중앙값으로 승자를 정한다.
- 승자를 고정한 다음 잠긴 test를 한 번 평가해 F2, recall, precision, 1.6초 ADE/FDE와 scene 단위
  95% 신뢰구간을 기록한다.
- 이 결과는 시뮬레이터 안의 예측 성능이다. 실제 급식실 안전 성능으로 표현하지 않는다.

## 2. 현재 데이터 감사 결과

아래 값은 실험 시작 전 로컬의 전체 120개 JSON을 읽어 확인한 값이다.

| 항목 | 확인 결과 |
|---|---|
| scene 구성 | 3개 레이아웃 × seed 40개 = 120개 |
| 사람 궤적 | 총 314개 track |
| 길이와 간격 | scene마다 150 frame, `dt=0.4s`, 잘못된 시간 간격 0건 |
| 현재 분할 | train 84 / val 18 / test 18 scene |
| 학습 창 | train 28,689 / val 6,550 / test 5,895 |
| safety 대상 | val 4,485개 중 위험 진입 361개(8.0%) |
| safety 대상 | test 4,015개 중 위험 진입 259개(6.5%) |

합리적인 점은 seed의 세 레이아웃 변형을 같은 split에 묶어 근사 중복 누수를 막았고, 위치 단위와
시간 간격이 일정하며, 경로 길이도 학습 계약에 충분하다는 것이다.

하지만 새 최종 성능을 주장하기에는 다음 문제가 있다.

- test 결과가 이미 공개되어 더 이상 완전히 잠긴 자료가 아니다.
- val에는 4명 scene이 있지만 test에는 없어 사람 수 구성이 다르다.
- val과 test의 작업 조합 비율과 위험 진입 비율이 다르다.
- 예전 `island` 40개에는 최신 파일의 `room`과 `robot` 정보가 없어 생성기 버전이 섞였다.
- 현재 모델 입력은 사람 한 명의 상대 x/z 이력뿐이다. 파일에 있는 작업, 목표, 레이아웃, 로봇,
  다른 사람 정보는 사용하지 않는다. 따라서 현재 데이터가 풍부해도 모델이 그 정보를 학습하지는 못한다.

결론적으로 기존 120개는 **v1 공개 벤치마크**로 보존하고, 자동 실험의 선택과 최종 보고에는 아래
v2를 사용한다.

## 3. 데이터 v2 구성

### 3-1. 생성 단위와 분할

현재 생성기 한 버전으로 50개 seed를 각 레이아웃에서 생성한다.

| split | seed | 레이아웃당 scene | 전체 scene |
|---|---:|---:|---:|
| train | 1~30 | 30 | 90 |
| validation | 31~40 | 10 | 30 |
| locked test | 41~50 | 10 | 30 |
| 합계 | 1~50 | 50 | 150 |

레이아웃은 실제 자유공간 모양이 다른 다음 세 가지다.

- `island_h58`: `sim.html?layout=island` (`half=5.75`가 현재 기본값)
- `corridor`: `sim.html?layout=corridor`
- `legacy`: `sim.html?layout=legacy`

`sim.html?layout=island`와 `sim.html?layout=island&half=5.75`는 같은 배치이므로 별도 레이아웃으로
세지 않는다. 또한 현재 `trajGeom()`은 corridor를 island로 기록하므로, 수집 전에 corridor의
`layout`과 `scene_id` tag를 별도로 기록하도록 고치고 회귀 테스트로 고정한다.

같은 seed의 세 레이아웃은 반드시 같은 split에 둔다. 생성기의 다섯 작업 조합이 seed 순서로
순환하므로 각 범위는 작업 조합을 균등하게 포함한다. 단, 이름만 믿지 않고 생성 후 실제 `jobs`, 사람
수, frame 수를 감사한다. 구성 비율이 다르거나 생성에 빠진 파일이 있으면 학습을 시작하지 않는다.

### 3-2. 저장과 기존 데이터 보호

- v1은 `dataset/trajectories/`에 그대로 둔다.
- v2 JSON은 별도 로컬 경로 `dataset/trajectories_v2/`에 쓴다.
- `/traj` 요청에 선택적인 `dataset` 필드를 추가한다. 허용값은 `trajectories`와
  `trajectories_v2` 두 개뿐이며 기본값은 기존 `trajectories`다. 그 밖의 값과 경로 문자는 거부한다.
- `__sim.trajRun`도 같은 값을 전달한다. v2 수집 명령은 항상 `dataset: "trajectories_v2"`를
  명시한다.
- 수집 시작 전 출력 경로를 화면과 로그에 표시한다. v1 경로를 가리키면 v2 수집을 중단한다.

### 3-3. 추적 가능한 manifest

대용량 JSON은 현재 정책대로 Git에 넣지 않는다. 대신
`docs/chanwoo/results/traj-v2-manifest.json`을 추적한다. manifest에는 다음을 기록한다.

- 데이터 버전, 생성 시각, 생성 코드 커밋, 생성 명령과 레이아웃 설정
- 파일명, split, seed, 레이아웃, 작업 조합, 실제 사람 수, frame 수, `dt`
- `room`, `robot`, 단위 정보 존재 여부
- 각 JSON의 SHA-256 해시
- split별 scene, 사람 수, 작업 조합 요약
- train과 validation의 양성/음성 safety 창 요약. 잠긴 test의 정답 기반 요약은 최종 평가 때만 추가

로더는 파일 누락, 추가 파일, 해시 불일치, 중복 seed/레이아웃, 같은 seed의 split 분산, 잘못된
`dt`/frame 수, 필수 메타데이터 누락을 발견하면 즉시 실패한다. 절대 조용히 v1이나 일부 파일로
대체하지 않는다.

이 구조는 현재 로컬 실험을 같은 파일로 다시 실행할 수 있게 한다. 데이터 파일 자체를 Git에 넣지
않으므로 다른 컴퓨터에 v2를 전달하는 일은 이번 범위 밖이며, 전달이 필요하면 별도 저장소와 접근
정책을 정한다.

## 4. 자동 실험 구조

공식 참고 저장소는 `karpathy/autoresearch` 커밋
`228791fb499afffb54b46200aca536f79142f117`로 고정한다. 이 저장소는 H100용 언어 모델 예제라 현재
궤적 코드나 의존성을 복사하지 않는다. 읽기 전용 참고 자료로만 둔다.

### 4-1. 파일 책임

| 파일 | 책임 | 자동 실험 중 변경 |
|---|---|---|
| `trajectory/autoresearch_candidate.py` | Transformer 후보와 `(paths, logits, logsig)` 출력 | **허용** |
| `train/autoresearch_contract.py` | 고정 데이터 로딩, 학습 설정, 지표, 보호 조건, 순위 계산 | 금지 |
| `train/run_autoresearch_experiment.py` | 한 후보 학습·validation·지연 측정·결과 기록 | 금지 |
| `train/audit_traj_v2.py` | manifest 생성과 무결성 검사 | 금지 |
| `docs/chanwoo/autoresearch-program.md` | 에이전트 작업 규칙과 keep/revert 기준 | 승인 후에만 변경 |
| `training/autoresearch/results.jsonl` | 모든 시도의 추가 전용 기록 | 기존 줄 수정 금지 |

후보는 현재 `LearnedPredictor`, K=3, 관측 8점, 예측 12점 계약과 호환되어야 한다. 고정 파일의
해시를 각 시도 전에 확인해 달라졌으면 실행을 거부한다. 자동 실험은 다른 워크트리나 브랜치에
`reset`, `checkout`, `clean`을 실행하지 않는다.

### 4-2. 한 시도의 순서

1. v2 manifest와 고정 파일 해시를 검사한다.
2. 후보 파일과 실험 설정의 해시, Git 커밋, 장치 정보를 기록한다.
3. 10개 준비 step 뒤 정확히 300초 동안 학습한다.
4. validation만 평가하고 F2와 보호 조건을 계산한다.
5. 결과 한 줄을 `results.jsonl`에 추가한다.
6. 보호 조건을 통과하고 현재 최고 F2를 넘으면 `keep`, 아니면 `revert`로 표시한다.

프로세스 전체가 600초를 넘으면 종료하고 `timeout`으로 기록한다. NaN, 무한값, 메모리 부족,
비정상 종료도 실패 사유와 마지막 로그를 기록한다. 결과 기록이 완성되지 않은 후보는 보존하지 않는다.
각 시도는 마지막 `keep` 커밋에서 시작한다. `keep`이면 후보 파일만 실험 ID와 함께 커밋하고,
`revert`이면 그 후보 파일만 마지막 `keep` 내용으로 되돌린다. `reset --hard`, `clean`, 다른 파일의
복구 명령은 쓰지 않는다. 무시되는 JSONL 기록은 어느 경우에도 되돌리지 않는다.

### 4-3. 탐색 예산

- 먼저 v2의 고정 LSTM, 현재 Transformer, 현재 CVAE 기준값을 같은 300초 학습 계약으로 각각 새로 잰다.
- 빠른 탐색은 후보 최대 20개 또는 전체 2시간 중 먼저 도달한 시점에 끝낸다.
- 빠른 탐색의 모델 초기화 seed는 하나로 고정한다.
- 상위 3개만 초기화 seed 3개로 다시 학습한다.
- 최종 순위는 3회 F2 중앙값, 동률이면 recall, 1.6초 FDE, CPU p95 순으로 정한다.
- test 데이터는 자동 실험 모듈에서 import하거나 선택할 수 없게 분리한다.
- 승자 코드와 설정을 커밋한 뒤 별도 최종 명령을 사람이 승인해 test를 한 번 실행한다.

## 5. 첫 탐색 범위

첫 단계에서는 Transformer 구조와 일반 학습 설정만 바꾼다.

- hidden 크기, encoder 층 수, attention head 수
- feed-forward 크기 비율, dropout, pre-norm 여부
- 마지막 token/평균 pooling
- learning rate, weight decay, batch 크기

hidden 크기가 head 수로 나누어지지 않는 조합은 실행 전에 거부한다. 다음 항목은 공정 비교를 위해
고정한다.

- v2 파일과 train/validation/test 분할
- 상대 좌표 정규화, 관측 8점, 예측 12점, K=3
- MTP 손실 계열과 safety 판정 반경·지평선·경보 방식
- 평가 코드, F2 계산, 보호 조건, 시간 예산

단순 Transformer 탐색이 정체되면 두 번째 단계에서만 GTrXL의 핵심인 **gate가 있는 잔차 연결**
(기존 표현과 새 표현을 섞는 비율을 학습하는 연결)을 작은 선택지로 추가한다. 강화학습용 GTrXL
전체 구조를 재현하지 않는다. Transformer가 지연 보호 조건을 계속 위반할 때에만 LSTM 구조 탐색을
별도 제안한다.

## 6. test 잠금

validation 실행 경로와 test 실행 경로를 코드 수준에서 분리한다.

- 자동 탐색 명령은 `train`과 `validation`만 받을 수 있다.
- locked test 파일명과 해시는 manifest에 있지만 일반 로더는 명시적인 최종 평가 token 없이는
  내용을 열지 않는다.
- 최종 명령은 선택된 후보 커밋과 설정 해시를 요구한다.
- 성공한 최종 실행 뒤 `docs/chanwoo/results/autoresearch-final.json`을 한 번 생성한다.
- test를 다시 실행하면 기존 결과가 있음을 알리고 기본적으로 실패한다. 재실행이 필요하면 이유와
  새 실행 번호를 문서에 남겨 최초 결과와 구분한다.

이 장치는 실수 방지용이다. 파일 접근을 암호학적으로 막는 보안 장치는 아니므로, 개발자는 test
수치를 보고 후보를 다시 고르지 않는 절차도 지켜야 한다.

## 7. 테스트와 검증

구현은 다음 자동 테스트를 먼저 추가한다.

- v2 파일 누락·추가·해시 변경·중복 조합을 manifest 검사가 거부한다.
- seed의 세 레이아웃이 한 split에 있고 90/30/30 scene과 작업 조합 균형을 만족한다.
- F2 계산과 네 보호 조건의 경계값이 정확하다.
- 후보가 `(B,3,12,2)`, `(B,3)`, `(B,3,12)` 출력을 낸다.
- 실패와 성공 모두 JSONL에 기존 줄을 보존하며 한 줄씩 추가된다.
- 자동 탐색 경로에서 test split 요청과 import가 거부된다.
- `/traj`의 기존 요청은 v1에 저장되고, 허용된 v2만 별도 경로에 저장되며 경로 조작 입력은 거부된다.

각 단계에서 전체 회귀 테스트도 실행한다.

```powershell
uv run --group serve --with pytest python -m pytest tests/ -q
```

실험 전후 v1 120개 파일의 SHA-256 목록을 비교해 하나라도 달라졌으면 결과를 폐기한다.

## 10. 구현 승인 뒤 순서

1. v2 저장 경로와 manifest 감사기를 테스트 주도로 구현한다.
2. 세 레이아웃에서 v2를 생성하고 무결성·구성 감사를 통과시킨다.
3. 고정 평가 계약과 test 잠금을 구현한다.
4. LSTM·Transformer·CVAE 기준값을 v2에서 다시 측정한다.
5. 후보 파일과 한 시도 실행기를 구현해 작은 연습 실행으로 기록·복구를 검증한다.
6. 20개/2시간 자동 탐색, 상위 3개 재검증, 승자 고정을 진행한다.
7. 사용자 승인 뒤 locked test를 한 번 실행하고 최종 보고서를 작성한다.
