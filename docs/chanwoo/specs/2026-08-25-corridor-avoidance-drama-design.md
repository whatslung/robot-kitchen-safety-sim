# 통로 회피 데모 — 임팩트 강화 설계 (확정)

> 2026-08-25 브레인스토밍에서 확정. 사람 움직임·로봇 회피기동을 "구름 밀도·음영처럼"
> UI로 보여주는 발표용 데모의 **임팩트 문제**를 푼다. 프로토타입으로 방향을 검증한 뒤
> 확정한 범위를 스펙으로 옮긴 것.

## 배경 — 요청과 진단

요청: 사람 움직임 시나리오 + 로봇 회피기동(실 회피기동)을 UI로 극적으로 보여주기.

시뮬을 실제로 돌려 진단한 결과, 요청한 기능은 **대부분 이미 구현돼 있다**:

| 기능 | 위치 | 상태 |
|---|---|---|
| 로봇 회피기동(hold/retract) | `AVOID` / `avoidDecide` | 있음 (통로 횡단 단계에서만) |
| 회피기동 화살표 | `RARR` / `robotArrowsUpdate` | 있음 (기본 꺼짐) |
| 사람 예측 밀도 구름 | `DENS` / `PRED` | 있음 (기본 꺼짐) |
| 예측 경로선·화살표 | `PRED.line` / `PMODE` | 있음 (기본 꺼짐) |
| 충돌 물리(사람 밀림) | `PUSH` / `demoPushCart` / `hzPush` | 있음 |
| before/after 발표 데모 | `DEMO_SCRIPTS` | 있음 |

**진짜 문제는 임팩트다.** 원인을 진단으로 나누면 **시나리오 60% + UI 40%**:

1. **로봇의 몸짓 자체가 작다 (시나리오/형태 — 근본 원인).** 로봇은 바닥 고정 페데스탈
   교반 팔이라 회피 수단이 `감속·정지·보류(hold)·후퇴(retract)`뿐이고, 자동차처럼
   **옆으로 비키는 곡선이 물리적으로 불가능**하다. 워크스페이스는 베이스
   `(-1.1, 0.81)` 중심 반경 **1.7m 구(球)** — 여기가 물리적 천장이다.
2. **진짜 회피는 7단계 중 1단계(통로 횡단)에서만, 순식간.** 교반 중엔 팔이 솥 위에만
   있어 사람 동선과 안 겹쳐 정지밖에 못 한다. `SEQ_FRY`의 `cross:true` 단계(카트로
   이송)만이 팔 동선과 사람 동선이 실제로 교차하는 유일한 구간이다.
3. **예측 구름이 로봇 결정과 시각적으로 안 이어진다 (UI).** 구름은 사람 쪽, 안전링은
   로봇 쪽에 따로 떠서 "사람이 여기 올 것 → 그래서 로봇이 이렇게 판단"의 인과선이 없다.
4. **로봇 기동 화살표가 솥에 묻힌다 (UI).** `RARR`는 TCP 바닥 투영에 그려지는데 교반 중엔
   그 위치가 솥 한가운데라 안 보인다.

## 프로토타입 검증 (버림)

브라우저 라이브 주입으로 확인한 사실(파일 수정·커밋 없음):

- 통로 횡단 단계를 **큰 아크**(솥 `(0,0.8,0)` → 높이 들기 `(0.05,1.55,0.95)` → 카트
  `(0.55,0.95,1.95)`)로 확대하면 IK가 오차 0.03 이내로 전 구간 도달 — 수평 ~2m·수직
  ~1.2m의 **꽤 큰 스윙**이 워크스페이스 안에서 가능하다.
- 통로에 사람을 세우고 before(휩쓸어 접촉)/after(급후퇴)를 GIF로 뽑으니, 위에서 팔이
  얼어붙던 것보다 확실히 **대비가 읽힌다.** 단, 여전히 고정 팔의 천장 안이다.
- 프로토타입이 바스켓을 기울인 것은 IK로 직접 몰며 손목 수평 보정을 건너뛴 탓 —
  실제 시퀀스(`stepUpdate`)는 `J4 = -(J1+J2)`, `J5 = 0` + 바스켓 요 추종으로 항상 수평.
  **실제 구현에선 문제없음.**

## 목표

통로 횡단 회피를 데모의 **주인공**으로 세우고, "피하지 않았다면 벌어졌을 일"과의
대비로 임팩트를 만든다. 자동차의 "휙 피함"에 대응하는, **고정 팔에 맞는 크래시 테스트형
연출**이다. 드라마는 로봇의 곡선이 아니라 **막아낸 참사**에서 뽑는다.

## 확정 범위

**포함**
- 큰 스윙 + 급후퇴 (별도 발표 모드)
- before 충돌 반응 (사람 휘청·쓰러짐, 기존 물리 재활용)
- 고스트 "피하지 않았다면" (반투명 유령 경로)
- 예측 → 결정 인과선
- 양념 — 경광등/알람, 위협감 카메라 프리셋, 회피 화살표 위치 보정

**제외**
- 슬로모 / 줌 / "충돌까지 0.5s" HUD (범위 확정 시 뺌)
- 로봇을 이동형/갠트리로 바꾸는 것 (연구 전제 위반 — 교반로봇은 고정 팔)
- ISO 안전링·정지/감속 판정 로직 변경 (연구 본체 — 손대지 않음)

## 설계

### ① 발표 모드 (연구용과 분리)

`PRESENT = { on:false, transit: 1.5, hardRetract:true, bigArc:true }` 를 추가한다.
켤 때만 데모 동작을 과장하고, **끄면 지금과 100% 동일**하다.

- **이송 속도**: `cross:true` 단계 한정으로 유효 속도를 ↑ (현행 협동 0.5 m/s → ~1.5 m/s).
  `stepUpdate`의 `state.seqT += dt * SAFE.factor * AVOID.rate` 에 발표 모드일 때만
  속도 배율을 곱한다. 다른 단계·다른 모드는 불변.
- **큰 아크 경로**: `cross:true` 단계의 목표를 발표 모드에서 위 3점 아크로 대체(관절 lerp
  대신 프레임당 `solveIK(arc(t))`). 손목 수평 보정·바스켓 요 추종은 그대로 적용.
- **급후퇴**: 발표 모드에서 `AVOID.rate`의 후퇴 값을 크게(빠른 역주행) + `SAFE.stopR`
  평활을 생략해 즉시 반응.
- **불변**: ISO 링(`SAFE.NOM_*`)·정지/감속 판정·학습 데이터 파이프라인.

### ② 통로 회피 데모 (주인공)

`통로 회피 데모` 버튼(우측 패널 "발표 시나리오" 옆)을 추가. 누르면:

1. 발표 모드 ON, 관련 표시(구름·경로선·회피 화살표·고스트·인과선) ON.
2. 카메라를 극적 3/4 저각 프리셋으로 고정
   (`target ≈ (0.30, 0.80, 1.05)`, `alpha ≈ -0.42`, `beta ≈ 1.14`, `radius ≈ 4.5`).
3. 사람 한 명을 통로 진입 지점 `≈ (0.75, 0, 1.75)` 로 걸어 들어오게 스폰(타이밍은
   로봇이 `cross` 단계에 드는 것과 맞춘다).
4. **before**: `AVOID.on = false` → 팔이 큰 아크로 휩쓸어 사람과 접촉 → `PUSH`/`personFall`로
   **사람 휘청·쓰러짐** → 상태 "충돌 — 회피 없음".
5. **after**: `AVOID.on = true` → 팔이 나가다 예측 발동 → **급후퇴** → 사람 안전 →
   상태 "회피 성공".

`DEMO_SCRIPTS`의 before/after 패턴을 그대로 확장해 넣는다.

### ③ 고스트 "피하지 않았다면"

after 재생 중, 회피가 발동한 프레임에서 **로봇이 회피 안 했다면 갔을 경로**를 그린다.
계획 경로는 이미 알고 있다(발표 모드의 아크 함수 또는 단계의 `from→to`). 그리는 것:

- 반투명 유령 바스켓 메시(실제 바스켓 클론, `alpha ≈ 0.3`)를 미래 t 위치에 배치.
- 유령 TCP 경로를 점선(`GreasedLine`)으로 사람 예측 위치까지 이어 그림.
- 실제(피한) 동작과 **한 화면에** 겹쳐 반사실 대비.

`RARR`와 같은 렌더링 규약을 따른다(`renderingGroupId = 1` — 설비에 안 가림).

### ④ 예측 → 결정 인과선

사람 밀도 구름이 로봇 경로와 겹치는 **침범 지점**을 `avoidMinDist`(이미 예측 혼합
`PRED.mix`에서 최근접 침범점을 계산)에서 얻어:

- 그 지점에 마커(작은 원/십자).
- 마커 → 로봇 TCP 로 연결선(`GreasedLine`).
- 라벨: "예측 진입 {t}s → 급후퇴" (기존 `AVOID.reason` 문자열 재사용 가능).

지금 따로 노는 구름과 로봇 판단을 "왜"로 잇는다.

### ⑤ 양념

- **경광등/알람**: 급후퇴 순간 기존 신호등(`lampApply`) 을 경고색으로 + 상태 메시지.
- **회피 화살표 보정**: `RARR.y` 를 솥 위로 올려(또는 TCP 실제 높이 사용) 교반 중에도
  안 묻히게. (부수)
- **위협감 카메라**: 데모 프리셋에 낮고 가까운 각을 옵션으로.

## 아키텍처 — 건드리는 것

`sim.html` 한 파일. 기존 시스템 위에 얹는다.

**재사용**: `AVOID`(후퇴)·`DENS`/`PRED`(구름·선·mix)·`RARR`(화살표)·`DEMO_SCRIPTS`
(before/after)·`PUSH`/`personFall`(충돌 물리)·`lampApply`(신호등)·`solveIK`·
손목 수평 보정 로직.

**새로 추가**:
- `PRESENT` 파라미터 객체 + 발표 모드 토글(UI 체크박스 1개).
- `cross` 단계용 큰 아크 경로 함수(발표 모드에서만 사용).
- 고스트 렌더러(유령 바스켓 + 점선) — `ghostUpdate()`.
- 인과선 렌더러(마커 + 선 + 라벨) — `causalLineUpdate()`.
- `통로 회피 데모` 연출 스크립트(사람 스폰 타이밍·카메라·before/after) — `DEMO_SCRIPTS`에
  항목 추가 또는 전용 함수.
- `통로 회피 데모` 버튼 + 발표 모드 체크박스(UI).

## 재현성·안전 영향

- 발표 모드는 **기본 꺼짐**. 끄면 기존 동작·데이터셋 생성·안전 판정이 100% 동일.
- ISO 안전링(`SAFE.NOM_STOP/SLOW/DANGER`)·정지/감속 판정·학습 데이터 파이프라인은
  **불변**. 발표 모드는 팔 이동 속도·경로·연출만 과장한다.
- 고스트·인과선·화살표는 **주석(annotation) 레이어** — 로봇 동작·안전 판단·학습
  데이터에 영향 없음(기존 표시 토글과 동일 원칙).

## 리스크·열린 질문

- **급후퇴 속도 상향 시 IK 안정성** — 프레임당 큰 목표 이동은 IK 진동을 부를 수 있다.
  아크 샘플 간격·`solveIK` 반복수로 완충 필요(프로토타입에선 iters 12로 안정).
- **사람 스폰 타이밍** — 로봇 `cross` 진입과 사람 통로 진입이 맞아야 대비가 산다.
  데모 스크립트에서 시각 동기(로봇 단계 이벤트에 사람 출발을 건다).
- **고스트가 화면을 어지럽힐 위험** — 반투명·점선·짧은 지속으로 억제. 필요하면 결정
  순간에만 잠깐 표시.
- **before의 충돌 물리 세기** — `PUSH` 파라미터가 발표에 과하거나 약할 수 있음. 데모용
  값 별도 조정.

## 검증

- 발표 모드 OFF → 기존 회귀 테스트(브라우저 스펙 `tests/browser/*.spec.mjs`) 그대로 통과.
- 발표 모드 ON → `통로 회피 데모` 로 before(접촉·쓰러짐)와 after(급후퇴·안전)가 각각
  재생되고, 고스트·인과선·화살표가 결정 순간에 보이는지 육안 확인(탑뷰 + 데모 카메라).
- 바스켓 수평 유지(J4·J5 보정) 확인 — 튀김이 쏟아지지 않는다.
