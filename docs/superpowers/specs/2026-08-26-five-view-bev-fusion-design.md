# 4+1뷰 사람 검출·BEV 글로벌 트래킹·미래예측 설계

## 1. 목적

현재 단일 선택 카메라 기반 모델 검증 경로를 다음의 CPU 시연 가능한 4+1뷰 파이프라인으로 확장한다.

```text
mvNW · mvNE · mvSW · mvSE + mvCenter
  → 공용 사람 검출기
  → 카메라별 ByteTrack
  → 바닥 Homography 투영
  → 중복 제거·글로벌 ID 융합
  → 글로벌 궤적별 기존 K=3 LSTM 멀티모달 미래예측
  → 미래 경로·불확실성·위험구역 진입 예상시간 출력
```

이 단계의 목표는 새 검출 모델의 최종 정확도를 주장하는 것이 아니라, 실제 검출 결과만으로 5개 카메라를 하나의 BEV 상태로 합치고 사람의 미래 경로까지 출력하는 런타임 수직 슬라이스를 만드는 것이다. 로봇 회피 기동은 별도 PR에서 구현되며 이번 범위에서는 건드리지 않는다.

## 2. 결정 사항

- CPU 시연은 기존 `backend/detect_server.py` Python 백엔드를 사용한다.
- 검출 모델은 서버 프로세스에 한 번만 로드하며 5개 카메라가 공유한다.
- CPU MVP는 batch=5 동시 추론이 아니라 한 번에 한 프레임을 처리하는 가중 round-robin을 사용한다.
- 선택 카메라는 새 4구획 준나디르 `mvNW`, `mvNE`, `mvSW`, `mvSE`와 중앙 위험구역 경사뷰 `mvCenter`다.
- 4구획 카메라는 방 전체 사람 recall을 담당하고 `mvCenter`는 로봇 주변 사람 크기·가림을 보강한다.
- 모든 뷰를 동일한 바닥 좌표계로 투영하되, 카메라마다 보정된 유효 바닥 polygon 안의 결과만 융합한다.
- 글로벌 상태 추정은 학습 모델이 아니라 Homography, 상수속도 Kalman, gated assignment로 먼저 구현한다.
- 기존 K=3 LSTM을 재사용한다. Transformer 도입과 새 LSTM 학습은 이 MVP 범위 밖이다.
- 온라인 위치 생성에서 SIM 사람 GT 좌표나 최근접 GT 사람 매칭을 사용하지 않는다. GT는 오프라인 오차 평가에만 사용한다.
- 출력은 로봇 제어를 직접 변경하지 않는다. 후속 회피 PR이 소비할 안정된 예측 계약만 제공한다.

### 2.1 확정 카메라 역할과 pose

4구획 카메라는 비교 프리뷰에서 천장 설비를 숨기지 않고 동일한 5명으로 검토한 결과다. 좌표 단위는 SIM scene unit이며 `fov`는 세로 화각이다.

| ID | 위치 `(x,y,z)` | 조준점 `(x,y,z)` | 세로 FOV | 역할 |
|---|---|---|---:|---|
| `mvNW` | `(-2.75,2.65,-2.75)` | `(-3.15,0,-1.14)` | 76° | 북서 구획 |
| `mvNE` | `(2.75,2.65,-2.75)` | `(4.37,0,-2.43)` | 76° | 북동 구획 |
| `mvSW` | `(-2.75,2.65,2.75)` | `(-2.23,0,4.32)` | 76° | 남서 구획 |
| `mvSE` | `(2.75,2.65,2.75)` | `(2.31,0,1.15)` | 76° | 남동 구획 |
| `mvCenter` | `(-1.10,2.65,3.80)` | `(-1.10,0.80,0.80)` | 70° | 로봇 중앙 위험구역 보조 |

`mvCenter`는 전체 방 커버 카메라가 아니다. 통로에서 로봇 쪽으로 접근하는 사람의 전신과 발 위치, 로봇 주변 가림 실패를 크게 보는 보조뷰다. pose가 바뀌면 해당 카메라 Homography는 즉시 무효화한다.

## 3. 현재 코드와 변경 경계

현재 `detect_server.py`는 공용 YOLO 모델, `/detect`, 카메라별 `CamState`, ByteTrack, 로컬 ID·이미지 속도를 이미 제공한다. 이 계약을 깨지 않고 확장한다.

현재 `sim.html`의 `milCapture()`는 선택된 카메라 한 장만 캡처하고, `milAssocTracks()`는 검출 박스를 SIM 사람 GT 위치에 최근접 매칭하여 월드 좌표를 얻는다. 4+1뷰 모드에서는 이 경로를 사용하지 않고 서버가 반환한 글로벌 BEV 트랙을 사용한다. 기존 단일 뷰·mock·브라우저 ONNX 모드는 회귀 방지를 위해 보존한다.

Python 책임은 다음처럼 분리한다.

- `backend/detect_server.py`: HTTP 계약, 모델 호출, 기존 로컬 ByteTrack 배선.
- `backend/multiview.py`: Homography 보정·투영, 글로벌 트랙 상태, assignment, 만료 정책.
- `sim.html`: 4+1뷰 카메라, 캡처 스케줄러, 카메라 보정점 등록, 응답·미래 경로 시각화, LSTM 호출.

## 4. 카메라 보정과 BEV 투영

### 4.1 보정 계약

서버에 `POST /calibrate`를 추가한다.

```json
{
  "camera": "mvSE",
  "coordinate_unit": "scene",
  "points": [
    {"image": [0.31, 0.72], "world": [-2.0, 2.0]},
    {"image": [0.68, 0.70], "world": [2.0, 2.0]},
    {"image": [0.59, 0.49], "world": [2.0, -2.0]},
    {"image": [0.39, 0.50], "world": [-2.0, -2.0]}
  ],
  "valid_world_polygon": [[-4, -3], [3, -3], [3, 4], [-4, 4]]
}
```

- `image`는 좌상단 원점의 정규화 좌표다.
- `world`는 공통 바닥 평면의 `(x,z)`다.
- 최소 4개의 비공선 대응점을 사용하고 DLT로 image→world Homography를 구한다.
- SIM은 고정 바닥 앵커를 카메라 영상으로 투영하여 대응점을 만든다. 사람의 실제 위치는 사용하지 않는다.
- 실환경에서는 같은 계약에 바닥 마커 또는 실측 대응점을 넣을 수 있다.
- 재투영 오차가 설정 한계를 넘거나 행렬이 특이하면 해당 카메라 보정을 거부한다.

### 4.2 사람 발 위치

사람 박스의 `(cx, cy + h/2)`를 발 위치로 보고 Homography로 변환한다. 결과가 카메라 유효 polygon 또는 전체 BEV 경계를 벗어나면 글로벌 융합에 넣지 않는다. 박스 자체는 디버깅을 위해 그대로 반환한다.

## 5. 글로벌 ID 융합

로컬 트랙의 식별자는 반드시 `(camera_id, local_id)` 튜플로 취급한다. 서로 다른 카메라의 같은 숫자 ID가 충돌해서는 안 된다.

각 글로벌 트랙은 다음 상태를 가진다.

```text
global_id, position(x,z), velocity(vx,vz), covariance,
last_seen, source_cameras, local_track_keys, history
```

업데이트 순서는 다음과 같다.

1. 글로벌 Kalman 상태를 측정 timestamp까지 예측한다.
2. 새 로컬 트랙의 BEV 위치와 예측 글로벌 위치 사이의 거리 비용 행렬을 만든다.
3. 설정된 거리 gate 밖의 조합을 금지하고 Hungarian assignment를 수행한다.
4. 여러 카메라가 짧은 융합 창 안에 같은 사람을 측정하면 confidence와 공분산으로 가중 보정한다.
5. 매칭되지 않은 측정은 새 글로벌 ID가 되고, 매칭되지 않은 글로벌 트랙은 제한 시간 동안 coast한다.

초기 기본값은 `gate=0.8 scene unit`, `fusion_window=250ms`, `coast=750ms`, `remove=1500ms`로 두고 환경변수나 설정으로 바꿀 수 있게 한다. 오래된 트랙은 안전 판단에서 조용히 정상값으로 취급하지 않고 stale/uncertain 상태를 반환한다.

ByteTrack이 아직 로컬 ID를 발급하지 않은 초기 person 검출도 BEV 측정으로 사용한다. 이 측정은 영속적인 `(camera_id, local_id)` 매핑만 만들지 않고 거리 gate로 기존 글로벌 트랙에 연결하거나 새 글로벌 트랙을 만든다.

## 6. HTTP 응답 계약

기존 `/detect` 요청과 박스 필드는 유지하고 `seq`, `t`, 글로벌 필드를 추가한다.

```json
{
  "camera": "mvSE",
  "seq": 31,
  "t": 1812.4,
  "image": "data:image/jpeg;base64,..."
}
```

`t`는 브라우저의 단조 시계 기준 밀리초다. 서버는 클라이언트 timestamp를 글로벌 상태 예측에 사용하고, 서버 도착 시각은 지연 측정에 별도로 기록한다.

```json
{
  "camera": "mvSE",
  "seq": 31,
  "boxes": [
    {
      "label": "person",
      "conf": 0.83,
      "cx": 0.52,
      "cy": 0.48,
      "w": 0.13,
      "h": 0.42,
      "id": 4,
      "global_id": 2,
      "world": {"x": -0.7, "z": 1.9}
    }
  ],
  "global_tracks": [
    {
      "id": 2,
      "x": -0.7,
      "z": 1.9,
      "vx": -0.1,
      "vz": -0.4,
      "age_ms": 42,
      "stale": false,
      "sources": ["mvSE", "mvCenter"]
    }
  ]
}
```

`GET /health`에는 로드된 모델, 보정 완료 카메라, 카메라별 최근 추론 시각, 평균·p95 지연, 글로벌 트랙 수를 추가한다.

`POST /tracks/reset`은 카메라별 ByteTrack과 글로벌 ID 상태를 비우되 모델과 Homography 보정은 유지한다. SIM 장면 초기화·인원 재생성 시 반드시 호출한다.

## 7. CPU 4+1뷰 스케줄러

영상 렌더링 FPS와 모델 검출 FPS를 분리한다. 동시에 여러 요청을 쌓지 않고 항상 최대 한 요청만 진행한다.

기본 스케줄은 다음과 같다.

| 카메라 | 목표 검출률 | 역할 |
|---|---:|---|
| `mvNW` | 4Hz | 북서 구획 |
| `mvNE` | 4Hz | 북동 구획 |
| `mvSW` | 4Hz | 남서 구획 |
| `mvSE` | 4Hz | 남동 구획 |
| `mvCenter` | 6Hz | 중앙 위험구역 보강 |

총 목표는 초당 22장이다. 서버 처리시간이 예산을 넘으면 과거 프레임을 큐에 쌓지 않고 다음 스케줄 슬롯을 건너뛴다. `seq`가 이전 응답보다 작거나 캡처 age가 제한을 넘은 응답은 표시·융합에서 버린다.

CPU MVP는 기존 PyTorch `.pt` 모델을 사용한다. ONNX Runtime, INT8, batch 추론은 동일 API를 유지한 후속 최적화다.

## 8. LSTM 연결

글로벌 트랙별 `(x,z,t)` 이력을 유지하고 기존 입력 규약인 8점·0.4초 간격으로 재표본화한다. `/predict`는 기존 단일 `{hist}` 요청을 유지하면서 선택적으로 `{tracks:[{id,hist}]}`를 받아 여러 글로벌 ID를 한 번에 반환하도록 확장한다.

배치 응답은 다음 계약을 사용한다.

```json
{
  "tracks": [
    {
      "id": 2,
      "age_ms": 42,
      "stale": false,
      "modes": [
        {"prob": 0.61, "sigma": 0.22, "path": [[0.4,-0.8,1.7],[0.8,-0.9,1.5]]}
      ],
      "risk": {"stop_entry_s": 1.2, "slow_entry_s": 0.4}
    }
  ]
}
```

`path`의 각 점은 `[미래시간초, world_x, world_z]`다. `risk`는 로봇 제어 명령이 아니라 예측 경로가 명목 정지·감속 반경에 처음 진입하는 시간이며, 진입하지 않으면 `null`이다.

미래예측 상태는 한 카메라의 로컬 ID가 아니라 모든 fresh 글로벌 트랙별로 반환한다. 이력이 부족하거나 예측기가 실패하면 해당 트랙은 Kalman 경로로 폴백하고 응답에 `source: "kalman"`을 표시한다. 이번 범위에서는 이 결과로 로봇을 직접 움직이지 않는다.

기존 LSTM은 첫 수직 슬라이스에서 그대로 사용한다. 최종 성능 평가 전에는 GT 궤적이 아니라 `검출→로컬 추적→BEV 융합` 오차가 포함된 궤적으로 미세조정한다.

## 9. 검출기 학습 단계

런타임 수직 슬라이스와 카메라 pose 확정 이후 4+1개 뷰의 동기화된 SIM 데이터를 생성해 공용 사람 검출기 하나를 학습한다.

- 같은 scene/seed에서 나온 5개 뷰는 반드시 같은 train/val/test split에 둔다.
- 카메라별 샘플 수를 균형화해 사람이 크게 보이는 `mvCenter`가 학습을 지배하지 않게 한다.
- 의상, 조명, 블러, 압축, 수증기, 가림, 카메라 pose·FOV를 랜덤화한다.
- 초기 모델은 기존 파이프라인과 CPU 배포성이 좋은 YOLO11s를 사용한다.
- RF-DETR은 교사 또는 GPU 정확도 비교군으로만 두고 CPU MVP 런타임에는 넣지 않는다.

현재 나디르 중심 가중치로 얻은 결과는 배선 검증값이며 최종 recall로 인용하지 않는다.

## 10. 실패·저하 처리

- 한 카메라 timeout: 해당 요청만 폐기하고 다음 카메라로 진행한다.
- 보정 미완료 카메라: 로컬 박스는 표시하지만 글로벌 융합에서는 제외한다.
- 검출 없음: 기존 글로벌 트랙을 coast 한계까지만 예측한다.
- 카메라 재배치: 기존 Homography를 무효화하고 재보정 전까지 융합을 막는다.
- 로컬 tracker 재시작: `(camera,id)` 매핑을 새 세대로 분리해 과거 글로벌 ID에 강제 연결하지 않는다.
- LSTM 실패: 글로벌 Kalman 경로로 폴백하고 상태에 predictor 오류를 노출한다.
- 서버 지연 증가: 요청 큐를 늘리지 않고 카메라별 실제 Hz를 자동으로 낮춘다.

## 11. 검증 기준

### 자동 테스트

- 4개 이상의 대응점으로 구한 Homography가 별도 바닥 점을 수치 오차 범위 안에서 복원한다.
- 서로 다른 카메라에서 같은 위치로 들어온 로컬 트랙 두 개가 하나의 글로벌 ID가 된다.
- 동일한 숫자의 로컬 ID를 가진 서로 다른 두 사람이 카메라 ID 때문에 충돌하지 않는다.
- gate 밖의 두 사람은 합쳐지지 않는다.
- out-of-order 응답, timeout, 카메라 dropout에서 ID 상태가 손상되지 않는다.
- 기존 `/detect`·`/predict` 단일 요청 계약이 유지된다.

### SIM 통합 검증

- 온라인 4+1뷰 경로에서 `person.node.position`과 `EXTRAS` 위치를 월드 좌표 생성에 사용하지 않는다.
- 메인 뷰를 바꿔도 백그라운드 4+1뷰 스케줄이 계속 동작한다.
- 한 사람이 두 카메라에 동시에 보일 때 BEV에는 하나의 fresh 글로벌 트랙만 표시된다.
- 4구획만 쓴 결과와 `mvCenter`를 더한 4+1 결과를 비교해 fused recall, 최대 blind gap, ID switch, p95 지연을 기록한다.
- fresh 글로벌 트랙마다 K=3 미래 경로 또는 Kalman 폴백 경로가 반환되고 위험구역 진입시간이 시간순으로 일관된다.
- CPU 시연 장비에서 렌더링이 추론 요청 때문에 멈추지 않고, 실제 카메라별 Hz와 응답 age가 UI에 표시된다.

## 12. 단계별 전달

1. **런타임 수직 슬라이스**: 4+1뷰 스케줄러, 보정, Homography, 글로벌 ID, 기존 LSTM 미래예측 연결.
2. **카메라 ablation·재배치**: GT 가시성·박스 크기와 4구획↔4+1 비교로 5개 pose를 고정.
3. **4+1뷰 검출기 학습**: 고정된 pose로 동기 데이터 생성, 공용 YOLO11s 학습, 뷰별·융합 recall 평가.
4. **엣지 최적화**: ONNX Runtime/INT8 또는 장치별 실행 제공자 비교.
5. **회피 PR 연동**: 이번 단계가 반환하는 글로벌 미래 경로·불확실성·위험구역 진입시간을 별도 회피 기동 PR의 입력으로 연결.

첫 구현 계획은 1단계에 집중한다. 2~5단계는 1단계가 실제 검출만으로 동작한 뒤 순서대로 별도 계획으로 진행한다.
