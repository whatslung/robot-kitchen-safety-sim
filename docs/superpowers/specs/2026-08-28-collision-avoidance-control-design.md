# 충돌·감속·회피 제어 재구축 설계

## 배경

PR #24(`7039136`)은 통로 회피를 큰 스윙, 고스트 경로, 인과선으로 과장한 발표용 연출이었다. 하지만 실제 문제는 연출 부족이 아니라 제어와 접촉 판정의 한계다.

- 팔 접촉은 현재 프레임의 수평 선분과 추가 인원만 검사해 대상과 프레임 사이 이동을 놓칠 수 있다.
- 거리 기반 감속률을 시퀀스 시간에 즉시 곱해 감속과 재가속이 불연속적으로 보인다.
- 로봇 회피는 `cross:true` 한 단계에서 출발 보류 또는 같은 경로 후퇴만 수행한다.
- 후퇴 경로가 막힌 경우 사용할 두 번째 안전 기동이 없다.

따라서 새 구현은 PR #24를 전체 revert한 기준에서 시작하며, 발표용 과장 동작을 복원하지 않는다.

## 목표

1. 주인공과 추가 인원 모두에 대해 팔의 실제 3차원 이동 궤적에서 일관된 접촉을 검출한다.
2. 거리와 예측 위험에 반응하는 감속·정지·재가속을 연속적인 속도 변화로 표현한다.
3. 위험 상황에서 `HOLD`, `RETRACT`, `SAFE_LIFT`, `STOP` 후보를 평가해 가장 낮은 비용의 안전 기동을 선택한다.
4. 핵심 계산을 Babylon 장면에서 분리해 빠르고 결정적인 단위 테스트를 제공한다.

## 제외 범위

- 이동 베이스, 갠트리 또는 로봇 기구 변경
- RRT, RRT*, CHOMP 같은 범용 온라인 모션 플래너
- PR #24의 큰 스윙, 고스트 경로, 발표용 고속 배율, 인과선
- ISO 인증 또는 실기 안전 성능 보증
- 기존 `SAFE.NOM_STOP`, `SAFE.NOM_SLOW`, `SAFE.NOM_DANGER` 수치 변경

## 구조

### 순수 제어 모듈

새 `safety_motion.js`는 Babylon 객체를 받지 않는 순수 함수만 제공한다. 브라우저에서는 전역 `SafetyMotion`으로, Node 테스트에서는 CommonJS export로 같은 구현을 사용한다.

- 벡터와 선분 최소거리
- 3차원 swept-capsule 접촉 검사
- 가속도 제한 속도 추종
- 위험 후보의 최소 여유거리 계산
- 후보 우선순위와 상태 전이 결정

`sim.html`은 씬의 관절·사람·예측 데이터를 평범한 숫자 객체로 변환해 모듈에 넘기고, 반환된 결정을 기존 시퀀스와 IK에 적용한다.

### 감지·미래 궤적 입력

기본 안전 제어는 YOLO, ByteTrack, 검출 서버를 사용하지 않는다. 시뮬레이터가 이미 가진 사람의
현재 위치와 남은 계획 경로를 제어용 ground truth로 사용한다.

- 자율 추가 인원: `P.root.position`, `P.path`, `P.pi`, `P.speed`
- 스크립트로 이동하는 주인공: `person.node.position`, `person.path`, `person.pi`, `person.speed`
- WASD 수동 주인공: 계획 경로가 없으므로 최근 실제 속도를 짧게 외삽
- 작업 체류·정지 상태: 현재 위치를 미래 시간창 동안 유지

남은 경로는 현재 위치에서 `path[pi]` 이후 웨이포인트를 순서대로 잇고 현재 보행 속도로
시간 매개화한다. 회피 제어는 이 미래 점유 궤적을 직접 사용하므로 시뮬레이터 내부 사람이
어디로 갈지 이미 아는 결정적 제어가 된다. 기존 칼만/LSTM 예측과 YOLO 기반 트랙은 모델
성능을 비교하는 선택적 검증 모드로만 남기며 기본 회피 결정을 덮어쓰지 않는다.

### 데이터 흐름

매 프레임 처리 순서는 다음과 같다.

1. 모든 사람의 캡슐과 시뮬레이터 계획 경로 기반 미래 점유영역을 수집한다.
2. 현재 로봇 단계에 대한 `PROCEED`, `HOLD`, `RETRACT`, `SAFE_LIFT` 후보 궤적을 만든다.
3. 후보 궤적과 사람 예측 점유영역 사이 최소 여유거리를 계산한다.
4. 안전한 후보 중 비용이 가장 낮은 기동을 선택한다.
5. 선택 결과로 목표 속도를 정하고 가속도 제한 필터를 적용한다.
6. 관절을 갱신한 뒤 이전·현재 팔 캡슐 사이 swept 접촉을 검사한다.
7. 접촉 시 로봇 정지와 기존 충돌/쓰러짐 처리를 수행한다.

## 충돌 판정

### 대상 통합

주인공과 `EXTRAS`를 하나의 사람 목록으로 변환한다. 각 사람은 다음 값만 노출한다.

```text
{ id, center:{x,y,z}, radius, halfHeight, source }
```

접촉 이후의 애니메이션과 상태 변경은 `source` 종류에 따라 기존 `personFall` 또는 `extraAct`를 호출한다. 판정 수학은 대상 종류를 구분하지 않는다.

### Swept capsule

각 로봇 링크는 이전 프레임 선분과 현재 프레임 선분, 링크 반경으로 표현한다. 링크 끝점 이동량이 4cm 이하가 되도록 시간축을 균등 분할하고, 각 샘플에서 링크 캡슐과 사람 캡슐의 3차원 최소거리를 계산한다.

- 여유거리 `<= 0`: 접촉
- 실제 팔 swept volume 밖: 비접촉
- 수평 위치가 같아도 높이 범위가 겹치지 않음: 비접촉
- 자동 시퀀스 여부가 아니라 링크 실제 이동량으로 `moving`을 판정

이 방식은 모든 방향에서 실제 팔 궤적에 들어온 접촉을 잡되, 베이스 반경 전체를 가짜 충돌 영역으로 만들지 않는다.

## 부드러운 감속

기존 반응형·예측형 계산은 `targetFactor`를 만든다. 실제 시퀀스 진행에는 별도의 `appliedFactor`를 사용한다.

- 감속 한계: 초당 2.5 factor 이하로 감소
- 재가속 한계: 초당 0.8 factor 이하로 증가
- 정지 명령: 안전을 위해 즉시 0 적용
- 해제 히스테리시스: 정지/감속 경계에서 0.15m 이상 벗어난 상태가 300ms 유지돼야 상위 상태로 복귀

상태 표시도 `targetFactor`가 아니라 실제 `appliedFactor`와 선택 기동을 사용한다. 로봇이 대기 중인데 “감속 중”으로 표시되는 현재의 불일치를 제거한다.

## 회피 후보와 선택

### 후보

- `PROCEED`: 원래 작업 경로. 위험이 없을 때만 선택한다.
- `HOLD`: 현재 포즈 유지. 위험 동작이 시작되기 전 우선 선택한다.
- `RETRACT`: 현재 단계의 진행도를 역방향으로 되감는다. 되돌아가는 swept path가 안전할 때만 선택한다.
- `SAFE_LIFT`: 현재 포즈에서 솥 상공의 사전 검증 안전 자세로 이동한다. 후퇴 경로가 막히고 안전 자세 경로가 비어 있을 때 선택한다.
- `STOP`: 어떤 이동 후보도 안전하지 않을 때의 최종 대기 상태다.

### SAFE_LIFT 자세

기존 도달 가능한 솥 상공 목표를 사용해 관절 목표를 계산하고, 시작 시점에 환경 장애물과의 간섭이 없는지 검증한다. 런타임 후보는 현재 관절값에서 안전 자세까지 보간한 12개 샘플로 구성한다. 샘플 중 하나라도 사람 예측 점유영역 또는 로봇 가드 장애물과 충돌하면 후보에서 제외한다.

### 선택 규칙

모든 후보는 같은 시간 지평선에서 평가한다. 팔 캡슐과 사람 예측 캡슐 사이 표면 여유거리가
`SAFE.C`(현재 0.15m) 이상인 후보만 안전한 이동 후보로 인정한다. `SAFE.NOM_DANGER`는
로봇 베이스 중심의 팔 도달 반경이므로 링크-사람 표면 여유거리 문턱으로 재사용하지 않는다.

1. 위험 없음: `PROCEED`
2. 위험 동작 시작 전: `HOLD`
3. 진행 중이며 후퇴 안전: `RETRACT`
4. 후퇴 위험, 안전 자세 경로 안전: `SAFE_LIFT`
5. 이동 후보 없음: `STOP`

한번 선택한 `HOLD`, `RETRACT`, `SAFE_LIFT`는 최소 300ms 유지한다. 더 위험한 상태로의 전이는 즉시 허용하되, 덜 위험한 상태로 돌아갈 때만 유지시간과 해제 히스테리시스를 적용한다.

## 인지 실패와 오류 처리

- 계획 경로가 없는 WASD 인원: 최근 실제 속도 기반 외삽과 현재 위치 기반 반응형 감속을 사용한다.
- 경로 인덱스·좌표·속도가 유효하지 않음: 해당 인원은 현재 위치에 정지한 것으로 보수 처리한다.
- 사람 검출이 명시적으로 실패한 사고 데모(`SAFE.blind`): 회피는 비활성화하지만 swept 접촉 감시는 유지한다.
- SAFE_LIFT IK 실패 또는 로봇 가드 간섭: 후보를 버리고 `RETRACT` 또는 `STOP`으로 폴백한다.
- 숫자가 유한하지 않거나 후보 데이터가 비어 있음: 이동하지 않고 `STOP`을 반환한다.
- 접촉 발생: E-STOP을 걸고 한 번만 충돌 반응을 재생한다.

## UI

실행 탭에서 현재 안전 동작과 원인을 표시한다.

- 정상 진행
- 감속 — 현재 속도 백분율
- 출발 보류 — 예측 진입 시간
- 후퇴 — 후퇴 경로 여유거리
- 안전 자세 — 후퇴 경로 차단
- 비상정지 — 안전 후보 없음 또는 접촉

기존 “로봇 접촉 사고” 버튼 묶음이 탭 라우팅에서 누락된 문제도 함께 고쳐, 실행 탭에서 충돌·끼임 재현 기능을 접근할 수 있게 한다.

## 테스트

### 순수 모듈 테스트

Node 기본 테스트 러너로 다음을 검증한다.

- 팔 궤적을 중심으로 여러 접근 각도에서 같은 접촉 결과
- 이전·현재 프레임 사이에만 존재하는 접촉 검출
- 수평으로 겹치지만 높이가 다른 경우 비접촉
- 남은 `P.path`를 보행 속도에 맞춘 미래 점유점으로 변환
- 경로가 없는 WASD 인원의 속도 외삽
- 잘못된 경로 입력을 현재 위치 정지로 보수 처리
- 감속과 재가속 기울기 제한
- 정지 명령 즉시 적용
- 경계 히스테리시스와 최소 상태 유지시간
- 안전한 후퇴 우선 선택
- 후퇴 차단 시 SAFE_LIFT 선택
- 모든 이동 후보 차단 시 STOP 선택
- 비정상 입력 시 STOP 폴백

### 브라우저 통합 검증

- 주인공과 추가 인원이 같은 접촉 판정을 사용한다.
- 감속 구역을 통과할 때 속도가 여러 프레임에 걸쳐 감소한다.
- 위험 동작 전에는 HOLD, 진행 중에는 RETRACT가 관찰된다.
- 후퇴 경로를 사람이 막으면 SAFE_LIFT가 실행된다.
- 모든 후보가 막히면 로봇이 정지한다.
- 사고 데모에서 인지는 실패해도 실제 접촉은 검출되고 E-STOP이 걸린다.
- 일반 조리·화재·데이터셋 흐름에 회귀가 없다.

## 완료 기준

- 새 순수 모듈 테스트와 기존 Python 테스트가 모두 통과한다.
- 브라우저에서 최소 한 번씩 `SLOW`, `HOLD`, `RETRACT`, `SAFE_LIFT`, `STOP`, 접촉을 재현한다.
- 같은 실제 팔 궤적에 놓인 사람은 접근 각도와 대상 종류에 관계없이 접촉으로 판정된다.
- 기본 회피 제어가 YOLO/ByteTrack 없이 남은 시뮬레이터 계획 경로만으로 동일하게 재현된다.
- 로봇이 정지해 있을 때 UI가 감속으로 표시되지 않는다.
- PR #24의 발표 전용 큰 스윙·고스트·인과선 코드는 남지 않는다.
