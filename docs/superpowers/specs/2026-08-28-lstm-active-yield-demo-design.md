# LSTM 고정 동선 능동 양보 시연 설계

## 1. 배경

현재 충돌 회피 제어는 시뮬레이터가 이미 알고 있는 `person.path`를 직접 읽어 사람의 미래 점유를 계산한다. 이 방식은 회피 제어 자체를 검증하기에는 결정적이고 안전하지만, 학습된 LSTM이 관측 이력에서 미래 동선을 예측해 로봇 행동을 바꾼다는 프로젝트의 최종 목적을 보여주지 못한다.

또한 현재 정책은 로봇 이동 초반에 위험을 예측하면 `HOLD`를 우선한다. 발표 화면에서는 버튼을 누른 뒤 로봇이 움직이지 않거나 오래 정지한 것처럼 보여, 감속·정지와 구별되는 능동 회피가 잘 드러나지 않는다. 파지된 바스켓도 현재 팔 링크 충돌 형상에 포함되지 않아, 로봇과 적재물을 합친 실제 작업 포락선을 판정하지 못한다.

## 2. 목표

- 전용 `고정 동선 LSTM 회피` 버튼을 누르면 로봇이 0.2초 안에 먼저 움직인다.
- 사람은 학습 데이터와 같은 결정적 직무 동선을 걸으며, 실제 LSTM `/predict` 출력이 로봇 회피 판단에 사용된다.
- 로봇은 예측 충돌에 대해 `RETRACT` 또는 `SAFE_LIFT`로 움직이며 양보한다.
- 사람이 지나간 뒤 0.3초간 안전하면 원래 작업을 즉시 재개한다.
- 파지 중에는 바스켓을 포함한 로봇 전체 작업 포락선을 예측·접촉 판정에 사용한다.
- 고정 동선을 막는 선반이 있으면 해당 시연에서만 비활성화하고 리셋 시 복원한다.
- WASD 사람 조작은 같은 LSTM 이력과 회피 제어를 사용하는 보조 실시간 시연으로 유지한다.

## 3. 비목표

- YOLO 검출 성능을 이 시연에서 다시 증명하지 않는다.
- 임의 장애물 주위를 돌아가는 범용 Cartesian/RRT 경로 계획기는 만들지 않는다.
- 안전한 후보가 하나도 없는데도 로봇을 억지로 움직이지 않는다.
- 일반 `자동 작업`의 기존 결정적 계획 경로 제어를 바꾸지 않는다.
- 모든 주방 선반을 영구 삭제하거나 기본 배치를 변경하지 않는다.

## 4. 검토한 접근

### 고정 동선만 사용

재현성과 발표 안정성은 높지만, 사용자가 즉석에서 방향을 바꾸는 상황에 대한 실시간 반응을 보여주지 못한다.

### WASD만 사용

상호작용성은 높지만 매 실행 결과가 달라 회피 성공 여부와 LSTM 기여를 비교하기 어렵다. 관측 이력이 충분하지 않은 초반에는 등속 폴백 비중도 커진다.

### 고정 동선 + WASD 보조 시연

채택안이다. 고정 동선은 실제 LSTM 출력과 능동 회피를 반복 가능하게 증명하는 주 시연으로 사용한다. WASD는 같은 입력 파이프라인이 온라인 방향 변화에도 재예측한다는 보조 시연으로 사용한다.

## 5. 데이터 흐름

주 시연의 제어 데이터 흐름은 다음과 같다.

```text
결정적 직무 동선 보행
  → 사람별 8스텝 × 0.4초 관측 이력
  → backend /predict의 LSTM 다중 경로
  → 신선한 예측 경로와 불확실성
  → 로봇+바스켓 후보 궤적 점유 비교
  → RETRACT / SAFE_LIFT / HOLD / STOP
  → 0.3초 안전 확인 후 원래 작업 복귀
```

시연 모드에서는 `person.path`의 미래 좌표를 회피 판단에 직접 사용하지 않는다. `person.path`는 사람 애니메이션의 실제 미래이자 사후 비교용 ground truth로만 남긴다. 제어 입력은 반드시 신선한 LSTM 응답이어야 한다.

일반 자동 작업은 기존 `person.path` 기반 제어를 유지한다. 따라서 LSTM 서버가 없어도 기본 시뮬레이터 안전 기능은 계속 동작한다.

## 6. 시연 시간표

- `0.0초`: 버튼 클릭과 동시에 로봇 자동 작업 시작
- `0.0~0.2초`: 첫 관절 값 변화가 발생해야 함
- `0.4초`: 사람이 먼 지점에서 결정적 고정 동선 보행 시작
- `0.4~3.2초`: 사람은 계속 걷고 로봇은 접근·파지 작업을 진행하며 관측 8스텝 축적
- `약 2.8초`: 로봇 바스켓 파지
- `약 3.2초 이후`: 실제 LSTM 예측 경로를 회피 판단에 사용
- `3~6초`: 사람의 로봇 작업영역 진입을 예측하고 능동 양보 기동 수행
- 사람이 위험영역을 통과하고 0.3초: 원래 이송 경로 복귀
- 마지막: 바스켓을 카트에 거치하고 홈 자세 복귀

LSTM 준비 시간을 별도 대기로 표현하지 않는다. 관측 이력은 로봇 파지 작업과 동시에 축적한다.

## 7. 회피 정책

판정 우선순위는 다음과 같다.

1. 실제 접촉 임박, E-stop 또는 SSM 정지 조건이면 `STOP`
2. 이미 작업 경로를 진행 중이고 후퇴 후보가 안전하면 `RETRACT`
3. 후퇴가 안전하지 않거나 이동 전이라도 상승 후보가 안전하면 `SAFE_LIFT`
4. 검증된 이동 후보가 없으면 `HOLD`
5. 선택 후보가 해제 여유를 0.3초 연속 만족하면 원래 경로로 복귀

이동 초반이라는 이유만으로 `HOLD`를 강제하지 않는다. 대신 바스켓과 설비까지 포함해 검증된 `SAFE_LIFT`가 있으면 능동적으로 안전 자세로 이동한다. SSM의 정지 결과는 언제나 이 정책보다 우선한다.

`RETRACT`와 `SAFE_LIFT`의 적용 속도 목표는 정상 속도의 60~65%로 한다. 기존 35~45%처럼 지나치게 느린 동작은 피하되 관절 제한과 즉시 정지 조건을 유지한다. 정상 시연에서 비상정지가 아닌 정지 상태가 0.8초를 넘으면 시연 실패로 기록한다.

## 8. LSTM 가용성과 폴백

전용 시연 버튼은 다음 시작 조건을 먼저 확인한다.

- `/health`가 성공해 백엔드가 가동 중임
- `window.__customPredictor`가 등록됨
- 예측 모델 선택이 `custom`임

시작 조건을 만족하지 않으면 `LSTM 서버 필요 — detect_server로 실행하세요`를 표시하고 능동 회피 시연을 시작하지 않는다. 시작 후 8스텝 관측이 쌓이면 `/predict`가 실제 모델을 지연 로드하며, 1초 이내의 신선한 응답을 받아야 사람을 위험 교차점으로 계속 진행시킨다. 모델 로드 실패나 응답 부재가 발생하면 사람은 위험영역 밖에서 멈추고 로봇은 안전하게 리셋한다. 전용 시연에서 칼만이나 시뮬레이터 계획 경로로 조용히 대체하면 LSTM을 사용했다는 오해가 생기므로 금지한다.

WASD 보조 시연에서는 8스텝이 쌓이기 전까지 등속 예측을 명시적으로 표시할 수 있다. LSTM 응답이 활성화되면 상태를 `LSTM 실시간 예측`으로 전환한다. 응답이 1초 이상 낡으면 즉시 안전한 로컬 폴백으로 전환하되 화면에 폴백 상태를 표시한다.

## 9. 고정 동선과 선반 처리

주 시연은 로봇의 바스켓 이송선과 한 번 교차한 뒤 위험영역을 빠져나가는 결정적 경로를 사용한다. 사람은 교차점에서 체류 동작을 하지 않으며 일정 속도로 통과한다. 같은 seed와 레이아웃에서는 동일한 A* 경로와 시간 순서가 재현되어야 한다.

시연 시작 전에 경로를 계산해 다음을 검사한다.

- 시작점과 종료점이 주 통행 연결요소에 포함되는지
- 로봇 작업영역 교차가 실제로 한 번 발생하는지
- 예정 시간 안에 위험영역을 빠져나오는지
- 선반 콜라이더 때문에 경로가 없거나 교차 시점이 깨지는지

선반이 원인인 경우 해당 `env_rack.glb` 인스턴스의 렌더 노드, 물리/사람 충돌체와 길찾기 장애물을 시연 동안만 비활성화한다. 이후 내비게이션 격자를 다시 생성하고 경로를 재검증한다. 제거 목록은 시연 상태에 저장하며 `리셋`, `해제`, 시연 종료 때 모두 복원한다. 선반 외 설비가 원인이면 자동 제거하지 않고 시연 시작을 실패 처리한다.

## 10. 파지된 바스켓의 안전 형상

`state.basketHeld`가 참이면 바스켓 작업 포락선을 로봇 링크 스냅샷에 추가한다. 바스켓 GLB의 세부 철망을 삼각형 단위로 계산하지 않고, 림과 몸체를 보수적인 캡슐 또는 여러 선분 캡슐로 근사한다.

같은 형상을 다음 두 경로에서 공유한다.

- 후보 관절 궤적의 LSTM 예측 점유 여유 계산
- 실제 프레임 간 swept contact 판정

파지 해제 즉시 바스켓 형상은 로봇 작업 포락선에서 제외한다. 잘못된 GLB 경계나 변환을 얻으면 안전 후보를 유효하지 않은 것으로 처리한다.

## 11. UI와 상태 표시

`실행` 탭과 발표용 영역에 `고정 동선 LSTM 회피` 버튼을 제공한다. 상태 표시 순서는 다음과 같다.

- `로봇 선행 작업`
- `LSTM 관측 3/8`
- `LSTM 예측: 1.2초 뒤 교차`
- `능동 양보: 후퇴` 또는 `능동 양보: 안전 상승`
- `경로 해제: 작업 복귀`
- `시연 완료: 충돌 없음`

예측 경로는 학습형 모드색 실선으로 표시하고 실제 사람 이동 경로와 구분한다. 칼만/등속 폴백은 회색과 명시적 라벨을 사용한다. 사용자는 화면만 보고도 어떤 예측기가 제어에 사용됐는지 알 수 있어야 한다.

## 12. 상태 복원과 오류 처리

시연 상태는 다음을 저장하고 모든 종료 경로에서 복원한다.

- 원래 예측 모델과 안전 입력 소스
- 로봇 자동 작업과 연속 작업 설정
- 사람 위치, 경로, 속도와 조작 모드
- 시연에서 비활성화한 선반 목록
- 바스켓 부모, 위치, 회전과 파지 상태
- 카메라와 UI 상태

중복 시작은 기존 시연을 먼저 정리한 뒤 새로 시작한다. 백엔드 오류, 경로 생성 실패, 안전 후보 부재는 각각 다른 상태 메시지로 보고한다. 실패 시 로봇은 현재 안전 상태를 유지하고 리셋으로 복구 가능해야 한다.

## 13. 테스트와 완료 기준

### 순수 단위 테스트

- 이동 초반 위험에서도 안전한 상승 후보가 있으면 `HOLD` 대신 `SAFE_LIFT`를 선택
- 후퇴 가능한 이동 중 위험이면 `RETRACT` 우선
- SSM 정지와 접촉 임박은 모든 능동 후보보다 우선
- 안전 해제 299ms에는 유지, 300ms에는 복귀
- 바스켓 파지 전후로 링크 스냅샷 형상 수가 정확히 변함
- 바스켓 형상만 사람 캡슐과 겹치는 경우도 충돌로 판정
- 오래된 LSTM 응답은 전용 시연에서 사용하지 않음

### 배선 테스트

- 전용 버튼이 로봇을 먼저 시작하고 사람 시작을 0.4초 지연
- 시연 제어 입력이 `person.path`가 아니라 신선한 LSTM 경로를 사용
- 일반 자동 작업은 기존 계획 경로 제어를 유지
- 선반 비활성화·내비게이션 재생성·리셋 복원이 모두 같은 시연 상태를 사용

### 브라우저 시나리오 테스트

- 클릭 후 0.2초 안에 관절 값 변화
- 관측 8스텝 후 실제 `/predict` 응답 사용
- 고정 동선이 로봇 작업영역을 한 번 교차
- `RETRACT` 또는 `SAFE_LIFT`가 최소 한 번 발생
- 비상정지 외 연속 정지 0.8초 이하
- 위험 해제 후 0.3초 내 원래 작업 복귀
- 로봇과 바스켓 모두 사람과 접촉하지 않음
- 최종 상태가 바스켓 카트 거치 완료
- 콘솔 오류 없음
