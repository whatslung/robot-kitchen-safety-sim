# LSTM 회피 시연 동선 방해 카트 제거 설계

## 목표

`▶ 고정 동선 LSTM 회피` 시연에서 사람의 고정 동선과 겹치는 주변 환경 카트를
임시 제거한다. 로봇이 바스켓을 내려놓는 작업용 카트는 시퀀스의 필수 설비이므로
대상에서 제외한다. 시연이 완료·실패·취소되거나 정지/홈 버튼으로 끝나면 임시 제거한
설비를 시연 직전 상태로 정확히 복원한다.

## 대상과 비대상

- 대상: `ENV_PROPS`에서 생성된 `env_pancart.glb`, `env_basketcart.glb` 중
  `demoRouteSamples(route)`의 사람 캡슐 여유 폭과 실제로 교차하는 인스턴스만 제거한다.
- 기존 동작 유지: 동선과 교차하는 `env_rack.glb` 선반도 계속 제거한다.
- 비대상: 로봇 바스켓 전달 시퀀스가 사용하는 작업용 카트, 동선과 겹치지 않는 환경
  카트, 다른 종류의 이동 물체와 설비는 건드리지 않는다.
- 카트가 없어도 A*가 유효한 경로를 찾는다면 불필요한 카트 제거를 하지 않는다.

## 상태 처리

선반은 기존처럼 holder와 정적 collider의 enabled 상태를 저장한 뒤 비활성화한다.
환경 카트는 동적 Havok proxy인 `PUSH.bodies[].box`가 실제 충돌 상태를 소유하므로
holder만 숨기지 않는다. 해당 카트의 위치, 회전, 선속도, 각속도와 pre-step 동기화
상태를 저장하고, proxy 전체를 방 바깥의 비가시 주차 위치로 옮긴 뒤 속도를 0으로 만든다.
한 물리 스텝 동안 메시→바디 동기화를 열어 렌더와 물리가 함께 빠지게 한다.

복원할 때 저장한 변환과 속도를 proxy에 되돌리고 같은 동기화 절차를 적용한다. 복원 후
`buildPersonColliders()`와 `buildNavGrid()`를 다시 실행해 사람 충돌과 A* 격자가 실제
설비 상태를 반영하게 한다. 중복 시작이나 여러 종료 경로에서도 복원 함수는 안전하게
여러 번 호출할 수 있어야 한다.

## 선택 절차

1. 현재 배치로 유효한 시연 경로가 있으면 아무것도 제거하지 않는다.
2. 경로가 막혔으면 샘플 점과 AABB가 겹치는 선반 및 대상 환경 카트만 수집한다.
3. 수집한 설비를 임시 제거하고 충돌/내비게이션 데이터를 재구성한다.
4. 동일 경로가 열렸는지 다시 검증한다. 열리지 않으면 기존 fail-closed 시작 실패를 유지한다.

## 검증

- 배선 테스트는 두 카트 파일 형식이 제거 대상이고 작업용 카트가 대상이 아님을 확인한다.
- 상태 테스트는 카트의 변환·속도·동기화 상태가 저장되고 모든 종료 경로에서 복원되는
  연결을 확인한다.
- 기존 JavaScript/Python 전체 테스트와 Playwright LSTM 종단 시나리오를 재실행한다.
- 브라우저 종단 테스트는 경로에 놓인 환경 카트가 시연 중 제거되고 취소 후 원래 위치로
  돌아오는지 확인한다.
