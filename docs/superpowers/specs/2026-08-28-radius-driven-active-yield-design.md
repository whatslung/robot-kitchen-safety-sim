# 반경 진입·이탈 기반 실시간 능동 회피 설계

## 문제

LSTM 회피기는 위험 시 `RETRACT` 또는 `SAFE_LIFT`를 선택하지만 최종 구동 합성에서
`SAFE.stopped`가 `approachFactor`의 즉시 정지 입력으로 다시 사용된다. 따라서 검증된
회피 속도 60~65%가 0%로 덮이며, 화면에는 회피가 아니라 정지만 보인다. 현재 고정 동선도
정지반경 3.10m 경계를 거의 스치므로 진입·이탈과 회피의 인과가 불명확하다.

## 선택한 방식

세 가지 가능한 방식 중 다음 정책을 채택한다.

1. **검증된 escape motion 허용 — 채택.** 물리 접촉 E-STOP은 절대 정지로 유지하되,
   LSTM 점유와 현재 모든 사람 capsule, 설비/바스켓 충돌 검사를 통과한 `RETRACT`와
   `SAFE_LIFT`만 정지반경 안에서도 제한 속도로 실행한다.
2. 정지반경 바깥에서 동작만 과장하는 방식은 실제 반경 진입 반응을 보여주지 못해 제외한다.
3. 미리 정한 관절 애니메이션을 재생하는 방식은 LSTM·실시간 거리와 분리된 연출이라 제외한다.

## 제어 합성

- `PHYS.estop === true`이면 어떤 모드에서도 즉시 0%로 정지한다.
- `STOP`, `HOLD`, 후보 검증 실패는 즉시 0%로 정지한다.
- `SAFE.stopped === true`여도 최종 선택 모드가 현재 프레임에서 안전성이 검증된
  `RETRACT` 또는 `SAFE_LIFT`이면 각각 최대 65%, 60%로 움직인다.
- `PROCEED`는 정지반경 안에서 허용하지 않는다.
- 선택된 escape 후보가 사람 또는 설비와 안전하지 않게 바뀌면 같은 프레임에 STOP으로
  악화한다. 단순히 이전 모드 이름만 보고 이동을 허용하지 않는다.
- 사람이 반경 밖으로 나가면 기존 300ms 해제 히스테리시스를 만족한 뒤 원작업으로 복귀한다.

## 시연 동선과 표시

- 사람은 감속반경 밖에서 출발해 감속반경과 정지반경을 차례로 통과한다.
- 횡단 레인은 정지반경보다 약 0.45m 안쪽을 지나되 팔의 물리 도달반경 밖에 둔다.
- 반대편으로 빠져나가며 `PROCEED → SAFE_LIFT/RETRACT → PROCEED` 전이가 한 번의
  연속 동작으로 보이게 한다.
- 상태 표시에는 `후퇴 회피 65%`, `안전 자세 회피 60%`, `안전 후보 없음 — 정지`처럼
  선택 모드와 실제 적용 속도를 함께 표시한다. 기존 SSM 메시지가 회피 표시를 덮지 않는다.

## 검증

- 순수 JavaScript 정책 테스트에서 정지반경 안의 검증된 escape는 허용되고, E-STOP·
  PROCEED·검증 실패는 즉시 정지되는지 확인한다.
- 배선 테스트에서 `SAFE.stopped`가 escape motion의 즉시 정지 조건을 다시 덮지 않는지 확인한다.
- 브라우저 테스트는 사람이 실제로 `SAFE.dist < SAFE.stopR`에 진입한 동안 관절 변화가
  발생하고, 모드가 `RETRACT` 또는 `SAFE_LIFT`이며, 접촉 없이 반경 이탈 후 원작업으로
  복귀하는지 확인한다.
